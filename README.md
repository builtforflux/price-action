# 价格行为交易方法

## 唯一入口

[从交易系统开始](trading_system/README.md)。这套方法以多空博弈为核心，将不同思想融会贯通，以 less is more 沉淀为最小充分的判断与执行流程。入口页说明方法定位、六个核心问题和各页用途。

使用 `trading_system/` 不需要先阅读 `reference/`。背景、位置或当前尝试的预期不清楚时，按问题查阅场景导航；场景名称不决定交易许可。

## 权威边界

Trading System 定义从市场事实、条件路径、交易方案、账户执行到复盘的运行规则。[Reference](reference/README.md)只保存来源、原始锚点、重复、冲突、核验状态和研究候选；它不直接决定交易。

数值知识必须先经治理流程发布且仍然适用，运行时才能使用。当前仓库没有生产级校准概率；不得把教学比例、形态重合或单笔结果写成当前胜率或盈利能力。详细边界见[复盘与治理](trading_system/governance.md)。

## 核心边界

- Market 持续判断位置、预期、实际进展和相关路径；Trade 构造交易方案并决定仓位怎样处理；Account 检查并执行订单授权，以平台记录核对实际仓位。
- 同一事实共享记录；不同关系增加的位置、次序、进展和跟随信息共同进入判断。重复命名本身不增加证据或预算；场景帮助判断，用例检验交接。
- 条件路径可以支持事前方案比较；入场、止损、出场、期限、成本和数量构成有利交换，所选参与条件满足且账户检查通过时，才授权建仓或加仓。
- 只有实际成交改变仓位。实际仓位归零且所有相关订单不再可能成交后，本笔交易才结束；市场、交易、账户和执行结果分别复盘。
