# Al Brooks 价格行为交易方法

本仓库把 Al Brooks 价格行为材料分成运行方法与来源证据两个不互相越权的部分：

| 入口 | 回答的问题 |
| --- | --- |
| [交易系统](trading_system/README.md) | 怎样从市场判断与双向方向机会运行到交易、风险关闭与复盘？ |
| [常见市场场景](trading_system/scenarios.md) | 已看清事实和状态时，怎样从六类共同因果问题形成双向机会？ |
| [来源证据](reference/README.md) | 知识来自哪里、条件是什么、怎样核验、有哪些冲突？ |

从[交易系统](trading_system/README.md)开始即可完整运行；Reference 只在离线核对来源、冲突或研究命题时使用。

## 权威边界

Reference 保存来源主张、原始锚点、重复、冲突、核验状态和待研究启发式；它不定义运行方法，也不直接决定交易。Trading System 决定知识怎样进入位置、测试、市场状态、双向方向机会、交易方案与复盘。

数值知识必须先由治理流程发布且仍然有效，运行时再核对当前目标、条件、周期、期限、判断时点和交易方案是否匹配。当前仓库没有生产级校准概率；当前使用定性判断，不伪造期望证明，也不自动禁止实际交易。详见[复盘与治理](trading_system/governance.md)。

## 不可违反的原则

- 市场事实与账户事实分别建立，只在交易决策和持仓管理时互相约束。
- 市场组织、位置、当前尝试、预期与实际表现、双向路径按因果顺序更新。
- Pattern、H/L、Wedge、Double Test、Flag、Triangle、MTR 等是可重合视图，不拥有专用交易流程，也不按名称重复计权。
- 常见形态和过程只归入六类因果场景；场景是按需形成方向路径的导航，不是新的运行状态。
- 方向机会、交易方案、交易决策、订单、成交、仓位、保护和结果各有唯一职责。
- 账户执行是提交前闸门和异常安全边界，不参与寻找机会；普通空仓新 K 不遍历完整账户流程。
- 初次入场、加仓、分段退出和余仓管理，都受当前市场路径与整仓风险约束；Market 完成目标实现后不保留 runner。
- 仓位归零后仍须结清所有可能改变仓位的订单并核对成交与费用，才能稳定关闭。
- 市场、交易、账户与流程结果分开结算。
