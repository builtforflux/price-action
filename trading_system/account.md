# 执行边界：检查、提交与核对

[Market](market.md) 说明市场正在发生什么，[Trade](trade.md) 决定是否参与、怎样参与以及当前唯一动作。Account 检查账户硬限制，提交 Trade 已授权的动作，并以平台权威事实核对真实结果。

本页所称“平台”，泛指提供订单、成交、仓位和保护权威事实的 Broker、交易所或交易终端。撮合、订单状态和平台级保护机制由具体平台负责。

## 盘中最小卡

```text
读取 Trade 当前唯一动作
→ 新增风险先检查账户硬限制和平台能力
→ 不允许：拒绝当前动作；允许：按授权提交、撤销或修改
→ 从平台权威事实读取订单、成交、仓位和实挂保护
→ 只有实际成交改变仓位；按实际余仓核对保护
→ 仓位归零且相关订单不再可能成交：风险关闭
```

Trade 没有新动作、平台权威事实也没有变化时，不运行 Account。手续费、滑点、净回报、目标、计划保护和候选数量由 Trade 算完整；Account 只核对当前动作是否允许和是否真实完成。

## 一、输入与输出

### 输入

- Trade 当前动作、方向、数量、价格规则、有效期和共同计划保护；
- 平台权威事实中的订单、成交、仓位、资金和保证金；
- 事前设定的单笔、总风险、日内损失、杠杆、清算缓冲和集中度等账户硬限制。

### 输出

- 当前新增风险允许或不允许，以及唯一理由；
- 实际提交、撤销或修改的订单；
- 平台确认的实际成交、仓位和实挂保护；
- 当前动作是否完成，风险是否关闭。

Account 可以因硬限制或平台无法安全表达方案而拒绝动作；方案变化交回 Trade 完整重构、等待或放弃。

## 二、账户硬限制

提交入场或加仓前只检查：

1. Trade 已授权当前一个动作，方向、数量、价格、有效期和保护明确；
2. 当前实际仓位与相关订单符合 Trade 使用的前提；
3. 整笔计划损失、总开放风险、日内损失、保证金、杠杆、清算缓冲、集中度和其他持仓限制全部通过；
4. 平台能够按已验证的方式表达入场、保护和退出。

任一必要事实不清、任一硬限制不通过或平台无法安全表达时，不允许新增风险。账户总风险至少计入实际仓位、仍可能增加风险的订单、当前交易已经实现的不利结果、适用成本，以及账户政策要求计入的其他暴露；未知不得按零处理。

减仓、全部退出、撤单或收紧保护只需确认动作会维持或降低风险。

每次实际成交、仓位、资金、保证金或清算边界变化后重新核对硬限制。若已确认违反，Account 立即取消仍可能增加风险的订单，并减到能够明确证明合规的数量；无法可靠确定合规余仓时全部退出。该安全动作只减少或关闭风险。

## 三、提交与平台事实

| 平台事实 | 只能说明什么 |
| --- | --- |
| 图表触及某价 | 市场发生触价 |
| 已提交订单 | 已向平台发出请求 |
| 平台已接受 | 订单存在并按平台规则工作 |
| Stop 已触发 | 触发条件成立，仍可能没有成交或只成交一部分 |
| 实际成交 | 仓位按成交数量变化 |
| 仓位显示为零 | 当前没有仓位，仍须核对相关订单 |

计划保护、已发送请求或图表触价都不能替代已经生效且覆盖实际仓位的止损。撤单请求也不等于订单已经取消。

Trade 授权动作后的处理只有：

- **入场或加仓**：通过新增风险检查后提交，按实际成交更新仓位并核对保护；
- **挂或收紧保护**：使用 Trade 给出的价格，确认保护已经生效并覆盖实际仓位；
- **挂止盈、减仓或退出**：只使用已验证不会扩大仓位或穿越零点的执行语义，按实际成交更新余仓；
- **撤单**：等待平台确认订单已经取消或不再可能成交，确认前不提交冲突动作；
- **等待平台确认**：不重复提交，也不从图表推断结果。

部分成交只按已成交数量改变仓位。未成交余量按 Trade 事前有效期和撤单条件保留或取消；每次实际余仓变化后立即核对保护覆盖。不能等计划数量全部成交后才建立保护。

减仓或退出前，先请求取消仍可能增加仓位的入场或加仓余量。撤单确认前出现迟到成交时，先按真实仓位恢复保护，再完成 Trade 已冻结的授权退出量或目标余仓；不得扩大比例分母或恢复原入场计划。

### 风险关闭

风险关闭条件只有一个：实际仓位为零，且所有本交易相关订单均已确认完成、取消或不再可能成交。状态未知、待撤单确认或存在未处理迟到成交时，不得关闭风险或开始同品种新交易。

## 四、平台事实不清时

底线是不在未知上增加风险：

1. 停止新的入场或加仓；
2. 查询平台权威事实中的订单、成交、仓位和保护；
3. 取消仍在工作的新增风险订单；
4. 已有非预期仓位时恢复已授权保护，或者使用已验证的只减仓语义减险或退出。

未知不能填成零。只有最大可能暴露已有足量且已确认的保护，并且下一次权威查询早于所有保证金、清算、交割、维护和连接可靠性硬期限时，才允许继续等待查询；否则存在可靠减险路径时立即减险或退出。无法可靠确定仓位数量时持续查询并联系平台支持方，不猜数量，也不盲发反向订单。

迟到或非预期成交一旦出现在平台权威事实中，就按当前实际仓位处理；它不构成新交易，也不能沿用此前“已关闭”的判断。

## 五、低频平台检查

启用一个新产品或账户时一次性确认：

- tick、数量步长、合约价值、费用、保证金和清算规则；
- 当前账户为已验证的 Netting / one-way 持仓模式；本流程不在 Hedging 模式新增风险；
- Stop、Stop-limit、原子 bracket、reduce-only、close-position 和原子 OCO 的真实语义；
- 首次入场或加仓能否原子建立保护；非原子例外必须事前明确最大未保护时间、最坏成交边界、确定性安全退出和权威确认时点；
- 部分成交后止损与止盈怎样保留或调整；
- 哪个界面或记录提供订单、成交、仓位和保护的平台权威事实。

没有验证清楚的平台能力不进入 Trade 方案。这些内容不在每根 K 或每笔交易中重填。

## 六、最小执行记录

执行记录只保留 Trade 授权、实际提交或撤销、实际成交与仓位、保护是否覆盖、风险何时关闭，以及执行是否偏离计划。费用和最终净结果直接使用平台记录。
