# 账户执行：下单与核对

> **本页是给人使用的执行清单，只负责账户风险许可、人的平台操作清单和执行结果核对。**

[Market](market.md) 说明市场正在发生什么，[Trade](trade.md) 决定是否参与、怎样参与和何时结束。Account 不重做市场判断，不改变交易方案，也不因为账户还有容量而创造入场或加仓。

本页所称“平台”，泛指提供订单、成交、仓位和保护权威事实的 Broker、交易所或交易终端。Trade 授权动作，Account 核对账户限制和执行结果，人操作平台，平台权威事实定案；撮合、订单状态和平台级保护机制由具体平台负责。

## 盘中最小卡

```text
Trade 当前授权：入场 / 挂止损 / 挂止盈 / 加仓 / 减仓 / 全部退出 / 撤单 / 无
新增风险：允许 / 不允许；唯一理由

平台权威事实：
- 仓位方向、数量、均价
- 仍在工作的相关订单
- 已生效止损的价格和覆盖数量
- 已生效止盈或减仓单

当前只做：一个明确动作 / 等待成交或确认 / 无
动作后核对：订单状态、实际成交、实际仓位、余仓保护
风险关闭：实际仓位为零，且所有本交易相关订单均已确认完成、取消或不再可能成交
不得关闭风险或开始同品种新交易：状态未知、待撤单确认或存在未处理迟到成交
```

运行顺序只有一条：

```text
读取 Trade 当前唯一动作
→ 新增风险先检查账户限制
→ 按授权提交、撤销或修改订单
→ 从平台权威事实读取接受、触发和实际成交
→ 只有成交后才更新仓位，并按实际余仓核对止损与止盈
→ 满足完整风险关闭条件后，关闭风险
```

普通新 K 不运行本页。只有 Trade 产生新动作，或平台权威事实中的订单、成交、仓位、保护发生变化时才回来核对。

## 一、唯一职责

### 输入

- Trade 已确定的动作、方向、数量、价格规则、有效期和计划保护；
- 平台权威事实中的订单、成交、仓位、保证金和资金；
- 事前设定的单笔、总风险、日内损失和杠杆等账户硬限制。

### 输出

- 当前新增风险允许或不允许；
- 已提交、撤销或修改的实际订单；
- 平台权威事实确认的实际成交、仓位和实挂止损；
- 当前动作是否完成；
- 风险是否关闭。

Account 可以因账户硬限制或平台无法安全表达方案而拒绝动作，但不能自行缩小合理止损、改成更小数量后提交、放宽保护、延长期限、创建目标或授权加仓。需要改变表达时把结果交回 Trade，由 Trade 完整重构、等待或放弃。

## 二、不能混淆的事实

| 看到什么 | 只能说明什么 |
| --- | --- |
| 图表触及某价 | 市场发生了触价 |
| 已发送订单 | 人发出了请求 |
| 平台已接受 | 订单存在并按平台规则工作 |
| Stop 已触发 | 触发条件成立；仍可能没有成交或只成交一部分 |
| 实际成交 | 仓位按成交数量变化 |
| 仓位显示为零 | 当前没有仓位；仍需核对所有本交易相关订单的最终结果 |

因此：计划止损不等于已生效止损，撤单请求不等于订单已经取消，止盈触价也不等于已经减仓。账户事实以平台权威事实为准，不从图表推断。

## 三、四个执行时点

### 3.1 提交入场或加仓前

本页只适用于已验证的 Netting / one-way 持仓模式；Hedging 模式不允许新增风险。首次入场或加仓必须能够以已验证的原子 bracket 建立保护；否则，只有产品级规则事前明确最大未保护时间、最坏成交边界、确定性安全退出和平台权威确认时点时才可例外。所有减仓和退出必须使用已验证不会扩大仓位或穿越零点形成反向仓位的 reduce-only、close-position 或原子 OCO。

只检查：

1. Trade 已授权当前这一个动作，方向、数量、价格、有效期和保护明确；
2. 当前仓位与相关订单和 Trade 使用的前提一致；
3. 整笔计划损失、总开放风险、日内损失、保证金、杠杆、清算缓冲、集中度和账户内其他持仓造成的限制均符合事前硬限制；
4. 平台能够按已验证的订单类型表达入场、止损和退出。

全部通过才允许提交。任一必要事实看不清、任一硬限制不通过或平台无法安全表达，结论就是“不允许”；不在 Account 内重构交易。

账户总风险至少计入当前实际仓位、仍可能增加风险的订单、当前交易已经实现的不利结果、适用成本，以及账户政策要求计入的其他持仓或风险；必要事实未知时不得按零处理。

减仓、全部退出、撤单或收紧止损不重跑新增风险判断，只确认方向和数量不会扩大仓位。

### 3.2 提交后或成交后

从平台权威事实直接确认：

- 订单是否被接受、拒绝、撤销或仍在工作；
- 实际成交数量和价格；
- 当前实际仓位；
- 止损是否已经生效并覆盖全部实际仓位；
- 止盈、减仓或其他退出单是否可能超过实际仓位。

每次实际成交、实际仓位、资金、保证金或清算边界发生变化后，Account 必须根据最新平台权威事实重新核对账户硬限制。已确认违反时，不等待新的 Trade 授权：立即取消仍可能增加风险的订单，并使用已经验证的 reduce-only、close-position 或其他只减仓语义，减到能够明确证明重新符合硬限制的数量；无法可靠确定任何合规余仓时，全部退出。

该硬安全例外只能减少或关闭风险，不能创建交易、加仓、放宽保护、增加目标或延长期限。

部分成交不产生新规则：只按已成交数量更新仓位，并按提交前已验证的保护路径确认实际仓位受到保护；再按 Trade 事前写明的有效期和撤单条件保留或撤销未成交余量。不能把“成交后马上挂止损”作为新增风险许可，也不能等计划数量全部成交后才处理保护。

### 3.3 Trade 给出账户动作时

| Trade 动作 | 人的执行与核对 |
| --- | --- |
| 加仓 | 再过一次新增风险检查；提交后按实际成交更新整仓和保护 |
| 挂或收紧止损 | 使用 Trade 给出的价格；确认新止损已生效且覆盖实际仓位 |
| 挂止盈 | 使用 Trade 给出的价格和数量；只使用已验证不会扩大仓位或穿越零点的 reduce-only 或原子 OCO |
| 减仓 | 使用已验证的只减仓语义按授权数量提交；只按实际成交减少仓位，并让止损覆盖余仓 |
| 全部退出 | 取消未成交的入场或加仓，使用已验证的 reduce-only 或 close-position；确认实际仓位归零 |
| 撤单 | 发出撤单后，等平台权威事实确认订单已经取消或不再可能成交；未确认前不提交可能冲突的替代单 |

执行减仓或退出前，先请求取消仍可能增加仓位的入场或加仓余量。撤单确认前出现迟到成交时，先按真实仓位补足保护，再完成 Trade 已冻结的授权退出量或减至其冻结目标余仓；不得扩大比例分母或恢复原入场计划。

Trade 没有新动作、平台权威事实也没有变化时，不操作 Account。

### 3.4 准备结束时

风险关闭条件：实际仓位为零，且所有本交易相关订单均已确认完成、取消或不再可能成交。状态未知、待撤单确认或存在未处理迟到成交时，不得关闭风险或开始同品种新交易。

手续费、资金费和最终净结果从平台记录进入复盘，不为此保留一个盘中“对账状态”。

## 四、平台权威事实看不清时

这不是一套异常状态机，只守一条底线：**不在未知上增加风险。**

1. 停止新的入场或加仓；
2. 刷新或查询平台权威事实中的订单、成交和仓位；
3. 取消仍在工作的新增风险订单；
4. 已有非预期仓位时，按可见实际仓位恢复已授权保护，或使用平台原生 reduce-only / close-position 退出；

未知不能填成零；保护数量、方向或状态未知时，不能假定风险已受控。只有最大可能暴露已有足量且已确认的保护，并且下一次权威查询早于保证金、清算、交割、维护和连接可靠性等所有硬期限时，才允许继续查询等待；否则，存在已验证的 reduce-only 或 close-position 路径时立即减险或退出。无法可靠定量退出时，持续查询并联系平台支持方，不猜仓位数量，也不盲发反向订单。

平台权威事实不清、出现非预期仓位或已确认违反账户硬限制时，这是唯一可以不等待新的 Trade 授权、由 Account 允许人执行的硬安全例外；只能停止新增风险、恢复已授权保护、减仓或退出，不能创建新交易。

迟到或非预期成交一旦出现在平台权威事实中，就按当前实际仓位处理：不把它解释成新交易，也不沿用此前“已关闭”的判断。

## 五、低频平台检查

启用一个新产品或新账户时，一次性确认：

- tick、数量步长、合约价值、费用、保证金和清算规则；
- 当前账户为已验证的 Netting / one-way 持仓模式；Hedging 不进入本流程；
- Stop、Stop-limit、原子 bracket、产品级非原子保护例外，以及 reduce-only、close-position 和原子 OCO 的真实语义与安全边界；
- 部分成交后止损与止盈怎样保留或调整；
- 哪个界面或记录提供订单、成交、仓位和保护的平台权威事实。

这些内容不在每根 K、每笔交易或每次复盘中重填。没有验证清楚的平台能力不进入交易方案。

## 六、最小执行记录

只保留[复盘与治理](governance.md)需要的事实：

- Trade 授权了什么；
- 实际提交、撤销或修改了什么；
- 实际成交与最终仓位；
- 止损和止盈是否按实际仓位生效；
- 风险何时关闭；
- 若执行偏离计划，偏离在哪里。

平台权威事实是账户事实来源；Account 不手工维护第二套订单生命周期或财务账本。

## 七、运行摘要

```text
Trade 给出唯一动作
→ Account 核对账户硬限制，人按 Trade 授权操作平台
→ 接受、触发、成交和仓位分别核对
→ 实际仓位始终有对应保护
→ 按 Trade 授权挂止盈、加仓、减仓或退出
→ 满足完整风险关闭条件后，关闭风险
```

Account 是薄的执行与核对页，不是第二套交易方法，也不是平台状态恢复系统。
