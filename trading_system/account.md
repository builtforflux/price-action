# 执行边界：检查、提交与核对

[Market](market.md) 判断市场，[Trade](trade.md) 决定仓位动作；Account 检查授权能否执行，核对实际仓位及本笔交易是否结束。

“平台”指 Broker、交易所或交易终端；“平台记录”指其订单、成交、仓位和实际止损记录。撮合、订单状态和止损机制由平台负责。

- **正常仓位动作** → 由 Trade 授权，Account 检查并执行。
- **账户硬限制已违反**，或**平台记录不清、无法安全等待且有可靠执行路径** → Account 可直接撤销扩仓订单并减仓或平仓；只缩小或清空仓位。

## 一、运行卡

```text
检查仓位动作、订单授权、账户限制和平台能力
→ 按依赖顺序执行允许的操作
→ 核对实际订单、成交、仓位和止损
→ 判断仓位动作是否完成、本笔交易是否结束
```

| 问题 | 输入 | 输出 |
| --- | --- | --- |
| 订单授权能否执行 | Trade 当前决定、目标仓位、订单授权、价格、期限和止损；账户硬限制与平台能力 | 可执行或不可执行及阻断原因；减仓、平仓、撤单或收紧止损还须确认不会扩大仓位或风险 |
| 平台实际怎样 | 平台订单、成交、仓位、资金、保证金和实际止损 | 实际提交、撤销、成交、仓位与止损；未知时的下一查询和最晚安全期限 |
| 本笔交易结束了吗 | 仓位动作完成情况、实际仓位及所有相关订单 | 本笔交易进行中或结束 |

手续费、滑点、净回报、计划出场价、全仓计划止损与候选数量由 Trade 算完整。

硬限制不通过或平台无法安全执行 → 拒绝建仓、加仓，由 Trade 另构完整方案、等待或放弃；已有仓位、订单与保护仍须处理。

等待确认时记录下次平台查询时间与最晚安全期限。授权和平台记录无变化，且查询与安全期限均未到，可结束本次处理；后续查询和保护继续，不表示本笔交易已结束。

## 二、账户硬限制

提交建仓或加仓前，以下条件必须全部满足：

1. 当前待提交订单已获 Trade 授权，方向、数量或目标仓位、价格、有效期和止损明确，与仍有效的授权相容；
2. 当前实际仓位与相关订单符合 Trade 使用的前提；
3. 整笔最大计划损失、总开放风险、日内损失、保证金、杠杆、清算缓冲、集中度和其他持仓限制全部通过；
4. 平台能够按已验证的方式执行建仓、止损、减仓和平仓。

账户总风险至少计入实际仓位、仍可能扩仓的订单、本交易已实现不利结果、适用成本及账户规则要求的其他持仓或订单；未知不按零处理。

- **必要事实不清、硬限制不通过或平台无法安全执行** → 不建仓、不加仓。
- **减仓、平仓、撤销扩仓订单或收紧止损** → 只需确认操作不扩大仓位或风险。
- **取消或替换保护性订单** → 保持实际仓位连续受保护。
- **取消止盈** → 不产生补仓授权。
- **实际成交或仓位变化，或价格、资金、保证金、清算边界变化足以影响限制** → 重新核对。
- **确认超限** → 立即取消仍可能扩仓的订单，减至可明确证明合规的数量；不能可靠确定合规余仓则全部平仓。安全动作只缩小或清空仓位。

## 三、提交与平台记录

| 平台记录 | 只能说明什么 |
| --- | --- |
| 图表触及某价 | 市场发生触价 |
| 已提交订单 | 已向平台发出请求 |
| 平台已接受 | 订单存在并按平台规则工作 |
| Stop 已触发 | 触发条件成立，仍可能没有成交或只成交一部分 |
| 实际成交 | 仓位按成交数量变化 |
| 仓位显示为零 | 当前没有仓位，仍须核对相关订单 |

止损须已在平台生效并覆盖实际仓位；计划、请求或触价均不能替代。撤单请求不等于取消确认。

首次建仓或加仓无法同步建立止损时，仅按[低频平台检查](#五低频平台检查)中事前验证的过渡安排处理。

Trade 订单授权的处理只有：

- **建仓或加仓** → 通过账户硬限制检查后提交，按实际成交更新仓位并核对止损。
- **挂或收紧止损** → 使用 Trade 给出的价格，确认止损已经生效并覆盖实际仓位。
- **挂止盈、减仓或平仓** → 只用已验证不会扩大仓位或穿越零点的下单规则，按实际成交更新仓位。
- **撤单** → 等待确认取消或不再可能成交；确认前不提交冲突动作。

提交后按实际事件接续：

- **等待平台确认** → 不重复提交，不从图表推断结果。
- **部分成交** → 只按成交数量更新仓位；余量按当前有效授权、有效期和撤单条件保留或取消。
- **实际余仓变化** → 立即核对止损覆盖，保护随首次和后续成交建立。

### 减仓、平仓与迟到成交

按以下顺序处理：

1. 先请求取消仍可能扩仓的余量。保护性止损触发或进入执行时，也同时终止旧扩仓授权并请求撤单。
2. 按已验证的只减仓方式处理实际仓位；紧急保护不等扩仓撤单确认。
3. 撤单确认前持续核对。发生迟到成交，先按实际仓位恢复保护，再执行到 Trade 在决定时确定的当前有效目标余仓。

例如持仓 200 减半，目标 100；迟到扩仓 50 后，从实际 250 减至 100。

- **其他退出使余仓低于目标** → 报告实际结果，不自动补回；目标只完成本次授权。

### 普通退出的取消与替换

Trade 以新完整方案更新普通止盈或主动退出时，保留原请求、已成交数量及各自时间。旧订单确认取消或不再可能成交前仍计入风险，不并行执行冲突授权；确认后才处理冲突的新授权，新方案只管理实际余仓。

- **迟到退出已减少仓位** → 按实际成交处理；买回须独立的新建仓或加仓授权。
- **保护性止损执行、账户超限或安全期限已触发必要减险** → 继续处理，不被普通方案更新替代。

### 本笔交易结束

- **实际仓位为零，且所有相关订单确认完成、取消或不再可能成交** → 本笔交易结束。
- **状态未知、待撤单确认或仍有迟到成交未处理** → 本笔交易继续，不开始同品种新交易。

## 四、平台记录不清时

底线是不在未知上建仓或加仓：

1. 停止新的建仓或加仓；
2. 查询平台记录中的订单、成交、仓位和止损；
3. 取消仍在工作的建仓或加仓订单；
4. 已有非预期仓位时恢复已授权止损，或者使用已验证的只减仓规则减仓或平仓。

只有同时满足以下条件，才可继续等待：

- 所有未决订单均成交后的最大仓位，已有足量且确认生效的止损覆盖；
- 下次查询早于所有保证金、清算、交割、维护和连接可靠性硬期限。

不满足等待条件，但有可靠执行路径 → 立即减仓或平仓。仓位数量无法可靠确定 → 继续查询并联系平台支持方，不猜数量、不盲发反向订单。

迟到或非预期成交出现时，按当前实际仓位处理；不另算新交易，也不沿用此前“已结束”的判断。

## 五、低频平台检查

启用一个新产品或账户时一次性确认：

- tick、数量步长、合约价值、费用、保证金和清算规则；
- 账户各项硬限制的计算口径与时点，特别是开放风险是否按当前价格到止损计算，以及已实现损失、其他持仓和未决订单怎样计入；
- 当前账户为已验证的 Netting / one-way 持仓模式；本流程不在 Hedging 模式建仓或加仓；
- Stop、Stop-limit、reduce-only、close-position，以及 bracket 和 OCO 是否保证相关操作一起生效的实际规则；
- 首次建仓或加仓能否同时建立止损；若不能，事前明确最长无止损时间、最坏成交边界、确定性平仓方式和平台确认时点；
- 部分成交后止损与止盈怎样保留或调整；
- 哪个界面或记录作为订单、成交、仓位和实际止损的核对依据。

能力未验证 → 不进入交易方案。已确认内容无需每根 K 或每笔重填。

## 六、最小执行记录

执行记录保留带时间的 Trade 授权及其变更、实际请求与确认、成交与仓位、止损覆盖、本笔交易结束依据，以及执行偏差。费用和最终净结果直接使用平台记录；汇总可压缩展示，原请求与成交轨迹仍可复核。
