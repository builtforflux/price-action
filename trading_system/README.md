# 交易系统

这是一套价格行为交易方法。它从当时可见的可靠事实出发，形成双向市场路径，只参与方案完整、交换有利且能够安全执行的交易。条件不足时，等待或放弃就是完整结果。

`reference/` 保存来源和研究材料，不参与盘中运行。当前方法使用定性判断，不承诺固定胜率或盈利能力。

首次使用某个账户或产品建仓前，必须完成 [Account 的低频平台检查](account.md#五低频平台检查)，设定账户硬限制，并验证持仓、止损、只减仓和组合订单的实际规则。

## 核心模型

系统按六个顶层问题运行：

1. **在哪里**：当前数据是否可靠，价格处于什么市场组织和重要位置？
2. **应该怎样**：若当前尝试成立，期限内应出现什么表现？
3. **实际怎样**：哪一方取得了进展，后续是否跟随并保住？
4. **可以去哪里**：多空分别有什么可达的路径目标、障碍和失效？
5. **是否值得交易**：能否用入场、止损、出场、期限、成本和数量形成有利交换？
6. **仓位怎样处理**：Trade 决定保持空仓、建仓、加仓、持有、减仓还是平仓；平台记录显示实际仓位和执行结果是什么？

由此形成唯一闭环：

```text
位置与当前尝试
→ 合理预期
→ 实际进展与跟随
→ 双向路径
  ├─ 等待形成 / 当前排除：停止本次处理
  └─ 至少一条路径完整：Trade 构造并评价交易方案
     ├─ 等待 / 放弃：停止本次处理
     └─ 较有利：Account 检查
        ├─ 不可执行：Trade 重新制定方案、等待或放弃
        └─ 可执行：执行订单授权并核对平台记录
           ├─ 本笔交易仍在进行
           │  ├─ 新市场事件 → Market 更新所选路径 → Trade 更新仓位动作；订单变化时回到 Account
           │  └─ 新平台记录或期限 → Account 核对执行
           └─ 本笔交易结束 → 分层复盘
```

只有平台确认的实际成交改变仓位。实际仓位为零，且相关订单均已完成、取消或不再可能成交时，本笔交易才结束。

## 分工

| 负责环节 | 回答什么 | 进入条件 |
| --- | --- | --- |
| [Market](market.md) | 在哪里、应该怎样、实际怎样、可以去哪里 | 首次分析、市场更新或完整重判 |
| [场景导航](scenarios.md) | 当前因果问题通常有哪些预期、竞争分支和候选区域 | Market 已知组织、位置和互动，却仍缺预期或路径；采用后返回 Market |
| [Trade](trade.md) | 是否值得参与，以及如何制定方案和调整仓位 | Market 至少有一条完整路径，或已有相关订单或仓位 |
| [Account](account.md) | 订单授权能否执行、实际仓位怎样、本笔交易是否结束 | 订单授权或平台记录变化，或查询与安全期限到达 |
| [复盘与治理](governance.md) | 各层结果如何评价，新知识是否值得改变方法 | 盘后 |
| [验收用例](examples.md) | 各环节之间的交接是否得到明确结果 | 验证边界时；不创造规则 |

同一事实只登记一次，同一结论只有一个负责环节。名称不增加证据；每个方向只有一条当前路径和一个路径目标；每次事件只有一个当前仓位动作。凡会改变判断、动作、计划损失或复盘结论的条件、顺序、例外和安全边界都必须保留——系统追求的是最小充分，而不是字数最少。

## 运行原则

- **先预期，后评价**：先确定当前解释的合理预期，再用实际进展与跟随判断测试、相对优势和路径。
- **按变化更新**：普通事件只更新被新事实改变的结论；数据边界、主测试、组织、阶段或关键结构被替代时才完整重判。
- **路径与交易分开**：Market 路径完整只允许 Trade 制定方案；止损、出场、成本和期限整体较有利后，才允许建仓或加仓。
- **判断与执行分开**：Trade 决定正常仓位动作，Account 按依赖顺序执行必要操作；订单、成交和实际仓位只认平台记录。账户硬限制已违反，或平台记录不清且无法安全等待时，Account 的安全动作只能撤销扩仓订单、减仓或平仓。
- **市场与交易结果分开**：Market 路径尚未得出最终结果时，本笔交易也可以先结束；复盘分别评价市场、交易、账户和执行过程。
- **未知时保持仓位安全**：平台记录不清或与计划冲突时，先查询并撤销可能扩大仓位的订单，再核对实际仓位和止损；不得把未知当作零。

没有可行路径就等待或排除；没有有利方案就等待或放弃；订单授权和平台记录都没有变化，且查询与安全期限未到，就停止本次处理。
