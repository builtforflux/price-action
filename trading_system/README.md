# 人工交易系统

这是一套给人盘中使用的价格行为交易方法，不是数据库字段说明或程序接口。

系统的认知重心只有两个：

- 判断市场现在怎样组织价格；
- 找到向上和向下是否存在可以交易的现实机会。

交易决策把机会变成风险明确的表达。账户执行只在提交前充当安全闸门，并在有订单、成交、仓位或异常时维护真实风险；它不参与寻找机会，也不要求空仓操作者每根 K 遍历完整账户流程。

即使没有 `reference/`，本目录也必须能够独立完成：

- 观察和判断市场；
- 形成、等待或排除方向机会；
- 选择或放弃交易；
- 执行和保护仓位；
- 处理新 K、Broker 事件和期限事件；
- 结束风险、完成对账并复盘方法。

系统不承诺固定胜率或盈利。市场事实不可靠、机会不完整、交易表达不完整或仓位不能可靠保护时，正确结果是不增加风险。

## 系统真正需要回答的问题

问题按因果顺序排列：

1. 价格在哪里，怎样到达，正在测试什么？
2. 多空双方谁在控制，市场处于什么状态？
3. 向上和向下分别可能现实地完成什么？
4. 哪个方向机会已经完整，哪个仍在等待，哪个应当排除？
5. 若参与一条完整机会，怎样入场、保护、退出并限制损失？
6. 新事实使所选机会增强、未变、削弱，还是终结？
7. Broker 实际接受、成交和保留了什么风险，风险是否真正结束？

前四问属于市场判断，第五问属于交易决策。第六问中，机会变化由市场判断裁决，持有、加减仓或退出动作由交易决策映射。第七问属于账户执行。后面的页面可以否决或安全收尾，不能倒过来重写前面的事实和判断。

## 统一运行链路

运行只有三个分支。箭头表示因果顺序，不表示要填写多张表。

### A. 空仓寻找机会

适用于没有实际仓位、也没有仍可能成交订单的状态。

```text
读取缓存的新增风险许可
→ 判断位置、空间、当前测试、多空压力、控制与主状态
→ 分别形成向上和向下机会
→ 将每个方向归为路径完整、等待形成或当前排除
→ 只有一边完整时直接作为候选；两边都完整时先比较两份最小可比表达
→ 选择至多一条候选路径
→ 为候选路径形成完整交易表达
→ 再选择交易、等待或放弃
→ 提交前通过一次账户最终闸门
→ 提交订单，或保持空仓
```

分支结果：

- 只有一条路径完整：先把它作为候选；保护、退出、成本和最坏风险完整后，才决定是否交易；
- 两条路径都完整：只为比较而分别确定参与条件、可行入场、合理共同保护、近端目标、成本和剩余时间；选择一条以后才展开完整方案，另一条不形成隐藏订单；
- 候选路径无法形成完整方案：可以返回仍然完整的另一方向评估一次；仍不成立时等待或放弃；
- 没有完整路径但存在等待形成的路径：记录下一事实和最晚等待时间；
- 两个方向都排除：放弃本次判断，不保留隐藏订单；
- 多空同时完整但无法唯一选择：有明确下一事件和期限时等待，否则放弃；
- 缓存账户许可为禁止：可以继续观察市场，但不能形成或提交新增风险订单。

提交前的账户闸门只确认本次交易必需的事实：实际仓位、仍可能成交的订单、风险容量、保证金与清算缓冲、Broker 能力，以及保护是否能够可靠建立。任一项未知或冲突，订单不提交。

订单一经提交，即使尚未成交，也进入“已有仓位或活动订单”分支。

### B. 已有仓位或活动订单

适用于存在实际仓位，或存在任何仍可能成交的订单。

```text
Broker 事件先重建真实订单、成交、仓位和保护
→ 期限到达时立即执行预定的取消、减仓或退出动作
→ 每根完成 K 完整更新所选方向机会，并扫描能削弱、否定或替代它的反方事实
→ 映射为保持订单、持有、加仓、减仓或退出
→ 账户执行按实际成交同步仓位、保护和剩余风险
→ 直到实际仓位为零且所有本交易相关订单都由 Broker 确认终止
```

每根完成 K 对所选机会只得出一种变化：

| 机会变化 | 默认处理 |
| --- | --- |
| 增强 | 继续原方案；增强本身不授权加仓 |
| 未变或正常回调 | 维持原订单或仓位管理 |
| 削弱但仍有效 | 取消尚未成交的新增风险；持仓按事前方案继续、减仓或更防御地保护 |
| 失效 | 取消新增风险并主动退出，不等待最远保护位置 |
| 实现 | 先取消全部新增风险订单，再执行原定退出；需要延伸时先形成新的市场路径和交易表达 |
| 到期 | 取消全部新增风险订单，并退出全部剩余仓位 |
| 替代 | 取消原路径新增风险并退出对应仓位 |
| 无法归类或市场数据不可用 | 取消新增风险并保持实际仓位的有效保护；事实无法归类时在下一规定期限前重建，数据不可用时在事前数据可靠性期限前恢复；到期仍不能可靠判断则全部退出 |

加仓不是“机会增强”的同义词。只有以下条件同时成立时，才允许执行事前方案中的加仓：

- 所选路径仍有效；
- 新的参与条件已经完成；
- 原方案预留了本次风险和最大总风险；
- 加仓后的全部仓位能够获得有效保护；
- 提交前账户闸门再次允许新增风险。

出场条件到达只授权退出总量，不等于退出已经完成。目标单触发、退出请求被接受或价格触及目标，都不能提前结束出场段。只有 Broker 实际成交才减少仓位。部分成交后，余单仍工作就等待；余单已终止但授权数量尚未全部成交，就按授权尚缺量和实际仓位中的较小值重新提交一次减险请求。全过程按实际余仓保持等量有效保护，本段累计退出不得超过授权总量。

在风险真正关闭以前，交易始终留在本分支并显示唯一管理动作。不能用“等待”或“放弃”隐藏仍存在的仓位、订单、保护责任或退出请求。

### C. 账户异常处置与安全覆盖

以下任一情况出现时，立即冻结新增风险并打开[账户执行](account.md)中的异常分支：

- 仓位、订单、成交或保护事实未知、过期或相互冲突；
- 实际仓位没有足量且可执行的保护；
- Broker 拒绝、断线、迟到成交、撤改单竞态或孤儿订单改变风险；
- 风险、保证金、清算缓冲或账户限制越界；
- 无法证明请求中的撤单、保护或退出已经生效。

异常分支只允许得到一个安全动作：核清事实、取消新增风险、恢复保护、减仓或退出。账户执行可以否决风险或使处理更保守，不能自行加仓、放宽保护、延长持有时间或创造市场目标。

异常解除后：

- 仍有仓位或活动订单：回到分支 B；
- 风险已经关闭：回到分支 A；
- 账户仍不允许新增风险：只能继续观察市场或管理既有风险。

## 三类唤醒事件

系统不是只在 K 线收盘时运行。

### Broker 事件

订单接受、触发、成交、部分成交、拒绝、撤单确认、更正、仓位或资金变化立即处理，不等待 K 线完成。它们优先重建实际订单、仓位、保护和风险。

### 期限事件

入场期限、等待期限、出场段期限、时间止损或订单有效期到达，是独立唤醒事件。即使发生在两根 K 之间，也必须立即执行事前规定的取消、减仓或退出，不能等下一根 K 才发现已经过期。

### 完成 K

完成 K 负责更新市场事实和方向机会。事先明确允许使用的未完成事件可以例外；否则未完成 K 不进入正式判断。

多个事件同时发生时，先按 Broker 权威事实重建风险，再处理已经到达的期限，最后根据可用的完成 K 更新市场判断。任何时候发现保护或账户事实不可靠，立即转入账户异常处置并执行安全覆盖。

[常见市场场景](scenarios.md)只是市场判断的查询视图：当位置、测试和状态已经明确，但仍不知道怎样组织双向机会时，选择与当前因果问题相符的分支。它只返回市场路径已有字段，不保存场景状态，不参与逐 K 更新，也不直接生成订单。

[验收用例](examples.md)负责检查页面交接是否得到唯一结果，不创造运行规则。

## 共同事实、不同职责

同一价格事实只记录一次，所有视图共享它。

例如 H2、Double Bottom、Bull Flag、Wedge、Triangle 或 MTR 可以同时描述同一段价格运动。它们不会因为名称不同而重复增加证据、概率或风险预算，也不各自建立一条交易流程。

仍需保留职责区别：

- 位置说明交易发生在哪里以及还有多少空间；
- EMA、回调比例、旧高低点和区间边界是位置或结构参照；
- H/L、双顶双底和楔形是对共同事实的结构视图；
- 测试说明价格正在验证什么，以及接受和失败怎样区分；
- 市场路径把事实、位置、测试和控制组织成一个方向的现实机会；
- 入场只说明何种新增事实授权参与，不能倒过来充当市场证据；
- 计划保护说明交易愿意承担风险到哪里，不等于市场路径失效，也不等于 Broker 已建立保护。

默认只有一个主测试。只有周期或测试对象、接受/完成条件、期限和下游影响都独立时，才保留第二测试；每个测试必须写明影响向上、向下或双方哪个机会，不能把标签、条件或证据拼成一条看似更强的路径。两个测试若会产生无法共享目标、失效和期限的同方向机会，应使用另一份观察边界明确的市场判断，不在一张人工卡中维护平行生命周期。

## 人工运行负担

### 需要完整展开

- 第一次判断或接管账户；
- 观察边界、主测试或市场结构重建；
- 首次选择交易或改变所选路径；
- 提交新增风险前；
- 订单、成交、保护或风险发生变化；
- 账户异常处置与安全覆盖、交易结束和复盘。

### 普通空仓新 K

只更新：

- 位置或空间是否改变；
- 当前测试是否推进、失败或结束；
- 多空压力、控制或主状态是否改变；
- 向上和向下机会的结果、下一事实或期限是否改变。

若没有下游变化，到此结束。无需打开完整账户执行页，也无需重写未变化的市场记录。

### 普通持仓新 K

只更新：

- 所选机会新增了什么事实；
- 全部新事实中是否出现能否定、削弱或替代它的反方事实；
- 结果是增强、未变、削弱还是终局；
- 事前方案映射出的唯一动作；
- 动作提交后等待哪个 Broker 确认。

OHLC、时间、订单号、成交号、仓位汇总、费用和版本关系应尽量自动取得。人工负责市场判断与选择，不负责复制平台数据或维护第二套订单账本。

## 不能混淆的边界

- 市场事实不等于结构视图；
- 形态名称不等于方向机会；
- 完整方向机会不等于交易许可；
- 市场失效条件不等于计划保护位置；
- 计划保护位置不等于 Broker 已确认的有效保护；
- 图表触价不等于订单触发或成交；
- 订单接受不等于仓位形成；
- 出场条件到达不等于出场成交；
- 撤单或退出请求不等于请求已经完成；
- 只有实际成交改变仓位；
- 仓位为零不等于风险已经关闭；
- 风险关闭不等于费用和现金已经对账；
- 单笔盈利不证明方法正确，单笔亏损也不证明市场判断错误。

风险只有在以下条件同时满足时才关闭：

- 实际仓位为零；
- 所有仍可能成交或状态未知的本交易相关订单均由 Broker 确认终止；
- 迟到成交、拒绝和更正等未决事实已经核清。

之后再完成费用、现金和成交对账。复盘分别评价市场判断、交易表达、账户安全和执行质量，不能用最终盈亏替代分层判断。

## Reference 边界

运行所需的定义、条件、例外、分支和安全动作都必须存在于 `trading_system/`。即使删除 `reference/`，系统仍能从观察市场走到风险关闭和对账完成。

`reference/` 只保存来源、历史数字、翻译、冲突和研究证据。它可以支持离线校准、审计和方法修改，不能成为盘中临时拼装规则的依赖。
