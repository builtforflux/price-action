# 交易系统

这是一套以多空博弈为核心的交易方法论：在当前背景与重要位置，双方正在尝试什么，取得多少进展，后续能否跟随并保住，对手又怎样回应。根据当时事实形成可检验预期，将入场、保护、出场、成本、数量和时间结合成交易方案，再根据真实执行反馈持续判断。

## 方法定位

融会贯通体现在决策关系中：理解每项思想的适用条件、比较对象、先后次序和实际作用，共享相同事实，保留会改变决定的区别。概念和名称帮助理解市场，规则直接说明依据什么、何时判断、怎样行动。

Less is more 追求最小充分：减少重复记录、无用分类和不影响决定的细节，让必要条件更容易看见和使用。能由现有结构清楚表达的内容归入现有结构；日常只展开当前问题需要的部分。

人或 LLM 等执行者均按当时可见事实运行这套方法。判断依据和取舍需要可说明，预期在结果出现前确定，新事实可以改变未来决定，历史记录保持原样。方法的逻辑、执行负担和交易效果分别通过复盘与实践检验。

首次使用账户或产品前，完成 [Account 的低频平台检查](account.md#五低频平台检查)，设定风险限制并验证执行与保护。历史回放、实时模拟和实盘练习从[训练与实盘运行](../practice/README.md)进入；该页负责取样、记录和晋级。

## 核心闭环

1. **在哪里**：数据是否可靠，背景和当前重要区域是什么？
2. **应该怎样**：如果当前解释成立，接下来应出现什么表现？
3. **实际怎样**：谁取得并保住进展，谁的尝试失败，跟随与对手表现改变了什么？
4. **可以去哪里**：什么条件下到哪个目标，途中有哪些障碍，怎样完成、失效或到期？
5. **是否值得参与**：入场、保护、出场、成本、数量与剩余时间能否构成有利交换？
6. **仓位怎样处理**：现在决定建仓、加仓、持有、减仓、平仓还是保持空仓，实际执行到了哪一步？

```text
可靠观察与重要区域 → 博弈、事前预期与实际进展 → 条件路径
→ Trade 构造并比较方案
   ├─ 等待或放弃当前方案 → 有实质变化时重评
   └─ 值得且满足授权条件 → Account 检查、执行、核对
      ├─ 未成交或部分成交 → 管理有效余单、实际仓位和保护
      └─ 退出完成且相关订单不再可能成交 → 交易结束与复盘

市场、价格交换、执行或期限有实质变化
→ 更新受影响的判断与方案 → 必要授权交 Account
```

市场判断在等待、持仓和未决订单期间继续。路径实现、交易退出和止损成交各自有条件：新判断可以改变未来管理，已经发生的预测、决定和成交保留原记录。

## 各页怎样使用

| 页面 | 负责内容 | 何时查阅 |
| --- | --- | --- |
| [Market](market.md) | 背景、位置、双方进展与条件路径；附录保留必要的几何与比较定义 | 首次观察和新市场事实到来时 |
| [场景导航](scenarios.md) | 六类常见问题的适用背景、竞争解释和区分事实 | 不清楚该预期什么或看哪些位置时，按问题查阅 |
| [Trade](trade.md) | 方案比较、风险与数量、参与和持仓重评 | 有依据的条件路径可供构造，或已有相关订单、仓位时 |
| [Account](account.md) | 账户限制、授权执行、真实订单、成交、仓位和止损 | 授权或平台记录改变，或查询与安全期限到达时 |
| [复盘与治理](governance.md) | 分别评价市场、交易、账户与执行；管理证据和方法变更 | 盘后及研究时 |
| [验收用例](examples.md) | 用连续事件检查各页交接 | 学习和验证规则时 |

平时只写影响当前决定的新内容；使用分批、加仓或特殊执行能力时，再展开相应细节。

[Reference](../reference/README.md) 保存思想来源、证据、解释分歧与核验状态；运行规则由本系统独立表达。当前方法使用定性判断，没有已校准的生产胜率；文档闭环和用例通过不证明盈利能力。
