# 交易系统

这是一套以多空博弈为核心的交易方法论：在当前背景与重要位置，双方正在尝试什么，取得多少进展，后续能否跟随并保住，对手又怎样回应。根据当时事实形成可检验预期，比较参与和管理方式，以真实仓位、成本和风险决定当前动作。

## 盘中决策入口

首次使用账户或产品前，完成 [Account 的低频平台检查](account.md#五低频平台检查)，设定风险限制并验证执行与保护。六问提示当前决定需要哪些判断，实际先后按下方[核心闭环](#核心闭环)处理。首次进入观察窗口时建立当前依据，后续只展开受新事实影响的部分，已有可靠内容直接沿用。

| 当前问题 | 决定所需内容 |
| --- | --- |
| **1. 在哪里** | 数据是否可靠，当前品种、周期、背景与重要区域是什么；这段运动在较大结构中起什么作用。 |
| **2. 应该怎样** | 如果当前解释成立，接下来应出现什么表现，允许哪些正常回调或停顿；什么异常会改变预期，最迟何时复查。 |
| **3. 实际怎样** | 谁取得并保住进展，谁的尝试失败，跟随与对手表现改变了什么；有此前预期时对照检验，尚未发生或无法确认的事实保留为待观察。 |
| **4. 可以去哪里** | 在什么条件下到哪个目标，途中有哪些实质障碍，怎样完成、失效或到期；只保留会改变选择的竞争路径。 |
| **5. 是否值得参与** | 空仓时比较参与与等待；持仓时比较继续持有与改变管理。用当下可执行价格、保护、出场、数量、成本和剩余时间判断交换；加仓先说明新增风险的补偿。 |
| **6. 仓位怎样处理** | 决定建仓、加仓、持有、减仓、平仓或保持空仓，写清目标余仓和必要订单；检查账户与执行条件，核对实际成交、余单和止损，确定下一次复查。 |

行为预期说明怎样的推进、回调或停顿支持当前解释；目标、障碍和时效说明可能取得什么回报。判断哪一方更可能推进，还要结合参与价格与管理方式评价交换。比较方案时若发现空间不足，可以研究更合适的参与条件，或补充有事实支持的路径；目标和合理保护各须有依据。

市场方向未变，当前价格交换也可能已改变；局部失望仍在计划允许范围内时，可以继续持有。调整入场或管理方式，要说明新事实改变了哪项前提或交换。单靠浮盈、浮亏或一次反色 K，不能替代这项比较。

## 核心闭环

首次观察时，先取得当时可见的市场事实和真实仓位、订单、保护状态。用已有事实建立当前解释，再为后续表现写出预期；后来的事实才用于检验这项预期，已经看到的行情不能补记为事前预测。已有持仓或订单时，同时接续其有效管理。

```text
当前事实与实际状态 → 先处理必须履行的执行与减险
→ 按需要建立或更新市场判断 ↔ 比较参与和管理方案
→ 决定维持或改变 → 执行必要操作并核对实际结果
→ 明确下一观察、查询或期限，结束本轮判断
→ 新事实或期限到来后，从受影响的部分继续
```

实际仓位、订单或保护不清时，先按 [Account](account.md#四平台记录不清时) 查询和保护，停止新增风险。平台事件、账户超限和安全期限立即处理；市场判断可以继续，必须完成的减险不等重新分析。

| 发生什么变化 | 从哪里继续 |
| --- | --- |
| 新完成 K 或允许的盘中事件 | 先以第 3 问对照此前预期；需要时更新第 2、4 问，再判断第 5、6 问是否要改变动作 |
| 方向未变，但价格、成本或剩余时间改变了交换 | 直接重算第 5 问；若目标可达性或失效也改变，再更新第 4 问 |
| 提交、撤单、部分成交或保护状态变化 | 先核对第 6 问的真实状态；数量或价格改变方案时重算第 5 问，未知或安全事件按 Account 立即处理 |
| 建仓或加仓订单有效期到达 | 结束相应扩仓授权、撤销未成交余量并核对；撤单确认前仍按可能成交处理，原市场路径可以继续观察 |
| 观察或市场路径期限到达 | 按原条件记录截至期限的表现；采用中的路径到期时重评持仓依据，没有及时成立的替代依据就退出 |
| 普通出场或交易期限到达 | 执行当前有效的出场规则；有新完整方案时，只按 [Trade 方案更新](trade.md#53-方案更新与尚未成交的退出)处理未成交余仓 |
| 安全期限到达、账户超限或保护性止损进入执行 | 先终止旧扩仓并完成必要减险；随后行情或数据恢复也不取消已触发的安全动作 |
| 背景、重要结构、观察周期或数据基础改变 | 回到第 1 问，重新建立判断；保留先前记录 |

空仓、无相关未决订单且缺少有依据的机会时，说明缺少什么、下一次何时重看，就可以结束本轮判断。复查可以等待区域互动、下一批可靠数据或既定时点。有仓位且原方案仍适用、没有实质变化时，沿用管理即可。当前动作已明确、必要操作已落实或有可安全等待的核对安排，且下一次观察或处理时机已确定，就停止继续展开；有效订单、保护与预定查询仍按原规则运行。

有依据的条件路径可以先构造方案，参与需要的确认由 Trade 选择。所需条件尚未满足时，只有平台能够准确实施该条件的完整方案才可预挂；普通触价单不能代替收盘、跟随或回试确认。首次授权前补齐 [Trade 运行卡](trade.md#二运行卡)，通过账户检查；等待后使用届时价格重算。

未成交或部分成交时，按实际仓位和仍可能成交的订单继续管理。本笔只有在仓位归零且相关订单均不再可能成交时才结束，同品种下一笔参与须先清理这些执行风险。市场判断持续进行，盘后把等待、退出与重入串回同一连续过程，分别评价市场、交易、账户和执行。

日常只记录影响当前决定的事实和变化，格式见[最小记录](../practice/README.md#五最小记录)。完整的持有、减仓和再次参与过程见[连续事件用例](examples.md)。

## 方法定位

融会贯通体现在决策关系中：背景决定合理预期，实际推进和对手回应检验预期，参与价格与管理方式决定承担哪种交换。不同思想共享相同事实，保留会改变选择的条件、尺度和先后次序；对参与者身份和动机的解释保留为推断。

Less is more 追求必要判断容易调用、动作有明确依据，并能在当前决定充分时结束分析。事实去重、只更新变化、复杂分层按需展开；保留会改变取舍的条件与尺度，以决定用时、漏做、无必要干预和成本后结果检验简化效果。页面和场景数量按使用需要调整。

人或 LLM 等执行者均按当时可见事实运行。预期在结果前确定，新事实可以改变未来决定，历史预测、授权和成交保持原记录。已弃用路径的结果可在盘后按原条件评价，盘中优先处理会改变当前动作的内容。

真实成交核对、连续保护和账户限制按 [Account](account.md) 执行。固定目标路径、单向持仓、全仓共同且不放宽止损、原预算不重置及净回报筛选按当前规则运行；它们的取舍与研究边界见[复盘与治理](governance.md#九当前回放重点)。

## 各页怎样使用

| 页面 | 负责内容 | 何时查阅 |
| --- | --- | --- |
| [Market](market.md) | 背景、位置、正常与异常表现、双方进展和条件路径；附录保留必要定义 | 建立或更新市场依据时 |
| [场景导航](scenarios.md) | 六类常见问题的适用背景、竞争解释和区分事实 | 不清楚该预期什么或看哪些位置时，按问题查阅 |
| [Trade](trade.md) | 当前动作与替代方案比较、风险与数量、参与和持仓管理 | 构造方案或当前交换改变时 |
| [Account](account.md) | 账户限制、授权执行、真实订单、成交、仓位和止损 | 授权或平台记录改变，或查询与安全期限到达时 |
| [复盘与治理](governance.md) | 分别评价四类结果、连续交易过程及方法变更证据 | 盘后及研究时 |
| [连续事件用例](examples.md) | 检查事实怎样改变动作及实际执行交接 | 学习和验证规则时 |

历史回放、实时模拟、最小数量实盘及加量从[训练与实盘运行](../practice/README.md)进入。执行能力与经济表现分别验收，合规批次不能替代加量所需的经济依据。

[Reference](../reference/README.md) 保存思想来源、证据、解释分歧与核验状态；运行规则由本系统独立表达。当前方法使用定性判断，没有已校准的生产胜率；文档闭环和用例通过不证明盈利能力。
