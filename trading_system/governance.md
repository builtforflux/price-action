# 复盘、证据与方法变更

本页只在盘后判断知识能否进入方法、交易怎样评价，以及方法怎样变更。盘中只运行 Market、Trade 和 Account。

## 一、知识进入方法前先拆清楚

每条知识必须回答五组问题：

| 问题 | 必须明确 |
| --- | --- |
| 描述什么 | 市场事实、结构关系、市场判断、方向路径、交易方案、账户事实或复盘指标 |
| 何时成立 | 产品、周期、比较对象、观察窗口、判断时点、前置、排除和期限 |
| 怎样变化 | 正常后续、确认、增强、削弱、失效和重置事实 |
| 能推出什么 | 实际改变的现有结论、仍缺的下游条件、共享事实、必要顺序和独立增量 |
| 现有原则能否生成 | 它是现有“位置—预期—进展—跟随—结果”链的新实例，还是无法无损表达的新机制 |

只有条件完整、确实改变运行结论，且现有原则无法无损表达其独立增量的知识，才增加新概念、状态或流程；其余归入现有入口、证据、研究候选或隔离。价格行为概念进入 Market 时还原为“可复核事实或关系 → 初始行为或跟随 → 对比事前预期 → 测试、相对优势或路径变化”，不另建同义状态。

### 新名称怎样归并

新形态、Setup、指标关系或案例只看它改变哪个现有结论：

| 实际改变 | 唯一去向 |
| --- | --- |
| 可见市场内容、判断或方向路径 | [Market](market.md)；场景只同步导航 |
| 入场、保护、退出、期限、质量、数量或管理动作 | [Trade](trade.md) |
| 账户限制、动作提交或平台订单、成交、仓位与保护事实 | [Account](account.md) |
| 尚不改变运行结论 | 证据、研究候选或隔离 |

每条知识只有一个运行入口和 Owner，同一事实登记一次。只有现有六类无法表达独立因果问题，且归并会丢失会改变下游决定的前提、竞争路径或终局时，才增加母场景；新名称、外观、参数或课程编号本身都不是理由。

## 二、三类知识分开处理

### 1. 结构关系

不声称精确概率、但条件和例外完整的可复核关系，可以写入唯一 Owner。多个名称只能合并共享事实；会改变结果的顺序必须保留，例如第二段陷阱不能删除“建立预期—第二段出现—限制位置跟随不足—重新接受旧区域”的先后。

### 2. 条件启发式

`likely`、固定根数、教学比例和无连续样本的经验数字，必须保留来源、产品、周期、时段、目标事件、判断时点、结果期限、例外、冲突和核验状态。信息不完整时只能作为定性参考、研究候选或隔离，不能成为当前交易的精确胜率。

### 3. 已校准的数值规则

数值只有完成完整发布条件，才可以进入生产判断：

- 规则版本和适用范围明确；
- 目标事件与互斥结果明确；
- 产品、周期、时段和判断时点一致；
- 前置与排除条件完整；
- 结果期限固定；
- 样本定义、数量、区间和缺失处理明确；
- 有不确定区间、漂移监控和停止使用条件。

**当前系统中可用于生产的已校准数值概率规则：没有。**

Reference 中的数字仍是证据或研究候选。没有合格数字时使用定性判断，不制造精确胜率，也不因此自动禁止交易。

## 三、三种概率对象

| 对象 | 回答的问题 | 必须匹配的边界 |
| --- | --- | --- |
| 市场结果概率 | 特定条件下，市场目标在期限内发生的可能性 | 产品、周期、判断时点、条件、目标事件和结果期限 |
| 交易结果概率 | 完整交易方案下，各互斥交易结果的可能性 | 入场、保护、退出、数量、成本与全部管理规则 |
| 状态或形态频率 | 某类状态或名称出现的频率 | 形态定义、观察窗口和样本范围 |

每个数值只回答所属对象。H2、Double Bottom、Flag 或 MTR 引用同一事实时按一组事实统计。

## 四、信息处置

每条信息只取一个结果：

| 结果 | 条件与动作 |
| --- | --- |
| 进入方法 | 明确改变运行结论或安全边界，且条件、例外和失效完整；写入唯一 Owner |
| 证据 | 有来源或教学价值但不改变运行状态；留在盘后材料 |
| 研究候选 | 可能有价值但缺样本、定义或校准；写明验证方法，验证前不生产使用 |
| 隔离 | 来源不明、条件缺失、冲突未解或会制造危险确定性；不得伪装成启发式 |

## 五、复盘时分开四个结果

Account 确认[风险关闭](account.md#风险关闭)后开始复盘；财务记录未齐时账户结果先标暂定。

| 结果 | 只记录 |
| --- | --- |
| 市场结果 | 路径待定、实现、失效、到期、替代或先后未知 |
| 交易结果 | 目标、保护、主动、时间、scratch、分批退出或无成交 |
| 账户结果 | 实际成交、费用、滑点、持有成本、换算和净结果 |
| 执行过程结果 | 判断和方案是否完整、风险是否合规、提交保护与管理是否遵守规则、平台未知时是否先核对 |

风险关闭时 Market 可能尚未终局。此时其他结果先复盘，原路径按冻结的目标、失效和期限只读跟踪；跟踪不授权持仓、再入场或修改历史，终局出现后再补全。

四个结果不能互相替代：

- 市场到达目标，不证明账户捕获收益；
- 赚钱，不证明判断和执行正确；
- 亏损，不自动证明市场判断错误；
- 被止损后市场路径仍可能最终实现；
- 单笔结果不能校准概率。

MAE、MFE、realized R 或 Actual Risk 只有在计算方法预先定义后才能作为事后描述；不得移动历史保护、补写风险、证明优势或修改概率。

## 六、最小复盘显示

| 区块 | 最小内容 |
| --- | --- |
| 当时看到 | 原市场判断、预期与实际表现、双向机会和最强反方事实 |
| 当时决定 | 交易、等待或放弃，以及入场、保护、退出、最大风险和管理规则 |
| 实际发生 | 订单、成交、仓位、实挂保护、成本、净结果和最早偏差或新事实 |
| 结论 | 方法不变、先修正执行或纪律，或形成研究候选 |

等待、放弃、未提交和无成交也可复盘；没有成交时不得补造盈亏。

## 七、方法变更

方法研究候选必须说明：

- 当前规则和可复现问题；
- 建议修改哪一个负责页面中的哪条命题；
- 适用条件、例外和风险后果；
- 支持与反对证据；
- 怎样连续收集全部命中实例；
- 怎样验收、停止和回滚。

发布顺序：

1. 固定事件、条件、结果和期限；
2. 连续收集样本，不能只收成功案例；
3. 检查重复、镜像、冲突，以及它实际改变的现有结论；
4. 通过场景、计算和必要的独立复核；
5. 发布新版本和生效时间；
6. 新规则只影响生效后的判断，不改写历史记录。

纪律、执行或平台设置问题由对应环节修正；市场方法只因可复现的市场命题而变更。

## 八、验收用例的地位
