# 复盘、证据与方法变更

本页只在盘后判断知识能否进入方法、交易怎样评价，以及方法怎样变更。盘中只运行 Market、Trade 和 Account。

## 一、知识进入方法前先拆清楚

理解一项思想后，按它是否帮助判断或执行评价其必要性：还原适用条件和决策作用，检查现有方法能否充分表达，再决定保留、合并、补充或研究。具体回答三件事：

| 问题 | 必须明确 |
| --- | --- |
| 它是什么 | 对象、产品、周期、比较关系、观察时点、前置、排除、期限，以及确认、削弱、失效和重置事实 |
| 它改变什么 | 位置、预期、进展、路径、交易方案、仓位处理或复盘结果，以及必要的条件顺序 |
| 为什么要新增 | 现有“位置—预期—进展—路径—交易—仓位”能否无损生成；不能时，独立增量是什么 |

条件完整、改变运行结论且现有核心无法表达独立增量时，才增加概念、状态或流程。其他内容并入现有入口，或归为证据、研究候选和隔离。价格行为概念进入 Market 时统一还原为“位置与尝试 → 合理预期 → 实际进展与跟随 → 路径变化”。

### 新名称怎样归并

新形态、Setup、指标关系或案例按实际改变的结论归入唯一负责页面：

| 实际改变 | 唯一去向 |
| --- | --- |
| 可见市场内容、判断或方向路径 | [Market](market.md)；场景只同步导航 |
| 入场、止损、出场、期限、质量、数量或仓位动作 | [Trade](trade.md) |
| 账户限制、订单授权执行或平台订单、成交、仓位与实际止损记录 | [Account](account.md) |
| 尚不改变运行结论 | 证据、研究候选或隔离 |

同一事实登记一次。只有现有六张场景卡无法表达独立因果问题，且归并会丢失会改变后续决定的前提、竞争路径或最终结果时，才增加母场景。

## 二、三类知识分开处理

### 1. 结构关系

不声称精确概率、但条件和例外完整的可复核关系，可以写入唯一负责页面。多个名称只能合并共享事实；会改变结果的顺序必须保留，例如第二段陷阱不能删除“建立预期—第二段出现—限制位置跟随不足—重新接受旧区域”的先后。

### 2. 条件启发式

`likely`、固定根数、教学比例和无连续样本的经验数字，必须保留来源、产品、周期、时段、目标事件、判断时点、结果期限、例外、冲突和核验状态。信息不完整时只能作为定性参考、研究候选或隔离，不能成为当前交易的精确胜率。

### 3. 已校准的数值规则

数值只有完成完整发布条件，才可以进入生产判断：

- 规则版本和适用范围明确；
- 目标事件与互斥结果明确；
- 产品、周期、时段和判断时点一致；
- 前置与排除条件完整；
- 结果期限固定；
- 样本定义、数量、区间和缺失处理明确；
- 有不确定区间、漂移监控和停止使用条件。

**当前系统中可用于生产的已校准数值概率规则：没有。**

Reference 中的数字仍是证据或研究候选。没有合格数字时使用定性判断，不制造精确胜率，也不因此自动禁止交易。

## 三、三种概率对象

| 对象 | 回答的问题 | 必须匹配的边界 |
| --- | --- | --- |
| 市场结果概率 | 特定条件下，路径目标在期限内发生的可能性 | 产品、周期、判断时点、条件、目标事件和结果期限 |
| 交易结果概率 | 完整交易方案下，各互斥交易结果的可能性 | 入场、止损、出场、数量、成本与全部管理规则 |
| 状态或形态频率 | 某类状态或名称出现的频率 | 形态定义、观察窗口和样本范围 |

每个数值只回答所属对象。H2、Double Bottom、Flag 或 MTR 引用同一事实时按一组事实统计。

## 四、信息处置

每条信息只取一个结果：

| 结果 | 条件与动作 |
| --- | --- |
| 进入方法 | 明确改变运行结论或安全边界，且条件、例外和失效完整；写入唯一负责页面 |
| 证据 | 有来源或教学价值但不改变运行状态；留在盘后材料 |
| 研究候选 | 可能有价值但缺样本、定义或校准；写明验证方法，验证前不生产使用 |
| 隔离 | 来源不明、条件缺失、冲突未解或会制造危险确定性；不得伪装成启发式 |

## 五、复盘时分开四个结果

判断与决定发生时保留记录；Account 确认[本笔交易结束](account.md#本笔交易结束)后汇总本笔交易。财务记录未齐时账户结果先标暂定。

| 结果 | 只记录 |
| --- | --- |
| 市场结果 | 原条件下的路径待定、实现、失效、到期或先后未知；停止采用另记时间与原因 |
| 交易结果 | 止盈、止损、主动平仓、到期、scratch、分批出场或无成交 |
| 账户结果 | 实际成交、费用、滑点、持有成本、换算和净结果 |
| 执行过程结果 | 判断和方案是否完整、计划损失与仓位是否合规、提交止损与仓位管理是否遵守规则、平台记录不清时是否先核对 |

本笔交易结束时 Market 可能尚未得出最终结果。其他结果先复盘，原路径继续按事前目标、完成、失效和期限评价。条件未发生导致到期时写明原因，与交易盈亏分别评价。现有数据无法确定目标与失效先后时保留未知，补充更细数据才可确认，不能用“替代”或账户盈亏填补。

**历史预测与当前采用分开。** 新事实可以使执行者停止采用旧判断、形成新路径或修改未来管理。记录新决定的时点、依据和实际余仓；原预测与已有请求、成交继续保留。新目标或期限从新判断开始，旧记录按原条件评价。继续研究市场、采用新判断和授权交易分别按负责页处理。

四个结果不能互相替代：

- 市场到达路径目标，不证明账户捕获收益；
- 赚钱，不证明判断和执行正确；
- 亏损，不自动证明市场判断错误；
- 被止损后市场路径仍可能最终实现；
- 单笔结果不能校准概率。

MAE、MFE、realized R 等事后描述使用预先定义的计算方法。盘中计算保留当时可见的端点、时点和用途；例如已发生回调形成的止盈参照按 [Trade 出场规则](trade.md#35-出场目标与期限)使用。历史止损、初始 R 与旧预测保持原记录，后续统计不反向证明事前优势。

## 六、最小复盘显示

| 区块 | 最小内容 |
| --- | --- |
| 当时看到 | 原市场判断、预期与实际表现、当时相关路径和最强反方事实 |
| 当时决定 | 参与、等待、放弃或持仓动作，以及入场、止损、出场、最大计划损失与有时间依据的方案变更 |
| 实际发生 | 订单、成交、仓位、平台实际止损、成本、净结果和最早偏差或新事实 |
| 结论 | 方法不变、先修正执行或纪律，或形成研究候选 |

等待、放弃、未提交和无成交也可复盘；没有成交时不补造交易收益，账户仍记录实际发生的费用。

一行摘要链接当时判断、历次决定和实际执行记录即可。复杂案例再展开截图与说明；摘要长度不决定原始证据是否保留。

## 七、方法变更

方法研究候选必须说明：

- 当前规则和可复现问题；
- 建议修改哪一个负责页面中的哪条命题；
- 适用条件、例外，以及对仓位和计划损失的影响；
- 支持与反对证据；
- 怎样连续收集全部命中实例；
- 怎样验收、停止和回滚。

发布顺序：

1. 固定事件、条件、结果和期限；
2. 连续收集样本，不能只收成功案例；
3. 检查重复、镜像、冲突，以及它实际改变的现有结论；
4. 通过场景、计算和必要的独立复核；
5. 发布新版本和生效时间；
6. 新规则只影响生效后的判断，不改写历史记录。

纪律、执行或平台设置问题由对应环节修正；市场方法只因可复现的市场命题而变更。

## 八、验收用例的地位

[验收用例](examples.md)只检查页面之间的交接。

用例与负责页面冲突时，以负责页面为准并修正用例。用例通过只证明给定条件得到明确结果，不证明盈利能力。

## 九、当前回放重点

条件路径、早期参与与未来管理调整已由运行页表达，其效果仍需在固定版本、连续取样和实际成本下验证：

- **确认与价格的交换**：对同一背景分别回放提前参与、收盘或跟随确认、回试参与；只使用各自当时价格。分别比较强背景下单次完成事件与更多跟随，以及早期反向 Swing 与控制转移后参与的条件和结果。
- **条件目标与后续管理**：比较近端出场、条件测量目标及目标实现后的余仓延伸；保留旧预测与旧请求，计入未成交、迟到成交、实际成本和回吐。Neckline 确认前采用投射、采用已发生回调的距离投射与其他结构目标、更新普通退出是否改善交易，仍需单独检验。
- **判断能否稳定执行**：不同执行者能否从同一可见事实解释预期、失败与当下决定；分歧保留为不同方案，避免把定性语言变成未经验证的评分。

另作研究比较：减仓后采用更远结构止损与先平仓再参与的总风险、成本和执行差异；净回报筛选在不同背景下排除了哪些方案、保留的方案是否仍缺少可达性依据。研究候选按上述方法变更流程验收，验证前继续执行当前限制。

单向持仓、全仓共用且持仓中不放宽止损、原预算不重置，以及净回报的保守筛选是当前方法选择。它们与平台必须核对真实成交和保护的事实边界分别评价；调整这些选择仍按方法变更收集证据。
