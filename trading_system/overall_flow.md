# 统一运行流程

> **Owner：从观察市场到交易结束的唯一因果顺序**

本方法只解决一件事：在重要位置上，根据价格怎样到达、正在测试什么以及双方怎样响应，形成上下两侧的现实路径；只有交易表达完整且风险值得承担时才交易，并用真实成交、保护和结果完成闭环。

```text
事实与观察边界
→ 位置与空间
→ 到达路径
→ 当前测试
→ 响应、压力与控制
→ 当前市场结构
→ 上下两侧现实路径
→ 交易表达与决定
→ 成交、仓位与保护
→ 持仓更新
→ 稳定结束与复盘
```

箭头表示因果顺序，不表示每一步都要填表。具体市场知识、交易构造和账户处理分别回到各自 Owner；本页不重复它们的字段、公式和例外。

## 一、先确认事实能够使用

开始前确认市场、时间、周期和账户事实可靠。

结果分支：

A. 市场资料不足，但已有仓位能够安全管理

→ 不形成新交易；有明确恢复事件则等待，否则结束当前判断

B. 仓位、订单、保护或账户连接无法确认

→ 停止新增风险；只核对、撤单、恢复保护、减仓或退出

C. 事实可靠

→ 开始市场读取

市场事实和账户事实始终分开：图表触发不能生成成交，计划价格不能证明订单在场，账户盈亏不能改写市场判断。

## 二、按因果顺序读取市场

### 1. 位置与空间

先问价格在哪里，上下最近的障碍、目标和可用空间是什么。位置是解释形状、信号和压力的第一坐标；同一事实出现在趋势内部、区间中部、区间边缘或旧极值附近，意义可以完全不同。

### 2. 到达路径

再问价格怎样来到这里：当前是推进、回调、暂停还是平衡；实体、收盘、连续性、分离、重叠和回调怎样变化；反方有没有取得持续响应。

### 3. 当前测试

用一句话说明：

```text
价格正在测试什么；怎样算接受；怎样算失败；下一项关键事实是什么？
```

典型过程：

```text
接近
→ 触及或短暂越过
→ 拒绝、突破、重叠或重新进入
→ 有跟随或无跟随
→ 接受 / 失败 / 继续未决
```

### 4. 响应、压力、控制与市场结构

根据测试后的实际表现判断：

- 原方向压力保持、增强还是减弱；
- 反方只是短暂反应，还是已经建立持续路径；
- 一侧减弱是否真的让另一侧取得控制；
- 当前仍是突破、通道或区间，还是已经发生结构转换。

每项新事实只从最早变化处向后传播：

1. 先判断它怎样推进或反对当前测试；
2. 再分别更新多头与空头 Pressure；一侧减弱不自动建立另一侧；
3. 压力关系已经改变持续推动能力时，才更新 Control；
4. 主导价格组织、正常回调、目标或管理方式被替代时，才重构市场结构。

形状只是同一事实链的不同视图。H/L 保存恢复次序，Double Test 保存复测区域和投射，Wedge 保存三次推动，Flag 或 MTR 保存外层作用；它们可以同时成立，但名称数量不增加证据或概率。

完整市场方法见[市场模型与机会](market_read_and_opportunities.md)。

## 三、形成上下两侧的现实路径

每一侧都回答：

```text
它想完成什么？
什么事实使它成立，并具备进一步构造交易表达的条件？
现实目标在哪里？
什么事实真正否定它？
最迟何时仍有意义？
已经发生的支持事实和最强反证是什么？
```

常见关系：

A. 两侧竞争，先获得接受的一侧改变另一侧；

B. 两侧顺序成立，例如先修正、后恢复原趋势；

C. 只有一侧完整，另一侧只有下一观察或排除原因；

D. 两侧都不完整，等待明确事件或结束当前判断。

市场机会描述可能发生什么，不是入场命令。同方向但目标、期限或判断周期不同，仍是不同机会。

## 四、决定是否交易

一条完整机会只有同时回答以下问题，才成为交易表达：

```text
为什么以及怎样入场？
现在应使用停止触发、提前限价、Trigger 后回试限价，还是 Market / close；为什么？
合理保护在哪里？
市场给出的现实目标在哪里？
本次承担多少数量和损失，整笔交易的风险上限是什么？
手续费、合理滑点和尚可能成交的订单如何计入？
持有、减仓、移动保护和退出的条件是什么？
```

结果互斥：

A. `TRADE`：机会已经激活，或所选订单触发能够完整实现尚缺的激活事实；同时表达完整，市场和账户风险都允许承担；

B. `WAIT`：当前不交易，也没有活动入场订单；但存在明确的下一事件和等待期限；

C. `STAND_DOWN`：当前没有值得承担或继续等待的交易表达。

市场目标概率不能直接代替特定入场、保护和退出下的交易结果概率。没有可靠数值时使用定性判断，不制造精确胜率，也不因此自动禁止人工交易。

交易构造、风险计算和唯一交易票据见[交易决策与计划](decision_and_plan.md)。

## 五、用账户事实完成交易

交易决定之后仍要区分：

```text
计划 ≠ 订单
图表触发 ≠ 实际成交
计划保护 ≠ 活动保护
市场触及目标 ≠ 账户捕获收益
```

账户闭环只有几条硬边界：

- 只有实际成交改变仓位；
- 部分成交立即形成对应仓位和保护责任；
- 活动保护必须真实在场、方向正确并覆盖全部仓位；
- 撤单或改单在确认前仍按原订单可能成交处理；
- 任一成交后都重新核对仓位、剩余订单、保护、费用和当前风险；
- 账户事实不可靠或保护不足时，停止新增风险并优先恢复安全。

持仓更新仍沿原链传播，不另建管理流程：

```text
新事实
→ 更新最早变化的市场环节与双向机会
→ 原表达未改变：持有
→ 新表达完整且整仓风险可接受：加仓
→ 表达恶化但机会未失效：按事前条件取消加仓、减仓或退出
→ 机会失效或竞争路径获得接受：退出；反向交易重走全链
→ 目标、期限或安全边界到达：按计划或安全要求处理
```

增加数量、延长期限、启用新目标或改变原管理承诺，都必须按当前市场重新形成交易表达并重算整仓风险；未经 Broker 确认的新订单或新保护不能视为已经生效。

完整账户边界见[执行、持仓与复盘](execution_management_and_review.md)。

## 六、稳定结束并分开评价结果

交易只有达到执行页定义的[稳定结束](execution_management_and_review.md#七稳定结束)，才进入最终复盘。账户稳定结束不必等待市场机会终结；机会仍有效时，之后补记最终市场结果。

市场、交易、账户和流程结果必须分开评价；具体判定与最小复盘由[执行、持仓与复盘](execution_management_and_review.md#八四类结果与复盘)唯一拥有。

赚钱不证明市场判断或流程正确，亏损也不自动证明判断错误；单笔结果不能校准概率。

## 七、人工更新只追踪变化

首次读取或市场结构重构时完整运行主链。普通盘中更新只问：

```text
发生了什么新事实？
它最早改变了位置、到达、测试、控制、机会、交易表达还是持仓动作？
如果没有改变任何下游结论，本次更新结束。
```

完整思考不能遗漏，但不要求反复抄写没有变化的内容。
