# 价格行为交易系统总流程

> **状态：Trading System / Runtime Contract**

本页是唯一运行入口。系统不选择某个预设策略，而是让当前结构生成目标事件和结果路径，再判断能否以合理风险交易其中一条路径。

```text
市场事件或账户事件
→ 同步运行边界与事实
→ 更新活动结构、位置和控制
→ 从结构生成候选目标事件
→ 建立同周期结果路径
→ 用新证据更新路径
→ 匹配目标事件的条件概率
→ 构造 Entry / Invalidation / Stop / Reward
→ 检查成本、时间、仓位和交易方程
→ 执行 / 等待 / 不交易
→ 订单、保护与持仓更新
→ 退出并记录决策和实际结果
→ 下一事件重新运行
```

## 一、系统的两个持续对象

### Market Path

Market Path 描述市场从当前结构与位置到一个明确目标事件的条件路径：

```text
Market Path

来源结构：
当前位置与参照区域：
接近方向：
目标事件：
目标区域及到达口径：
观察周期：
预计时间范围：

已经成立的条件：
支持事实：
最强反方事实：
增强所需的新事实：
削弱所需的新事实：
失效条件：
当前条件概率：
概率替代条件：

状态：不存在 / 观察 / 可构造交易 / 削弱 / 失效 / 已完成
正在等待：
```

同一结构可以生成多条 Market Path。只有目标事件、周期和时间范围相同的路径才能直接比较或使用更具体条件替代旧概率；不同 horizon 的路径可以同时成立，但不能把它们的概率、Entry 或目标拼成一笔交易。

### Trade Plan

Trade Plan 是一条 Market Path 在当前判断时点的风险实现：

```text
Trade Plan

选择的 Market Path：
判断时点：
方向：

Entry：
Invalidation：
Planned Protective Stop：
Targets 与退出数量：
Position Size：
总账户风险：
成本与滑点假设：
Scalp / Swing 与持有时间：
Management：
Outcome Criterion：
Trader's Equation：

订单有效期与取消条件：
成交后保护激活方式：
异常处理：
```

Trade Plan 不能改写 Market Path。Entry、Stop、Target、概率、仓位、成本和管理必须来自同一判断时点；任一输入改变，都要按当前价格重新计算整份计划。

## 二、事件驱动边界

系统不只由新 K 线驱动。以下事件都可能要求更新：

```text
完成新的观察 K 线
重要价格区域被接近、触及或越过
新的结构边界形成或失效
订单被确认、拒绝、取消或部分成交
实际成交、保护状态或账户仓位改变
风险预算、Session 或剩余时间改变
```

价格事件更新 Market Path；订单与账户事件更新 Trade Plan 的实际执行状态。账户事实不能从图表推定，图表触发也不能证明账户已经成交或受到保护。

## 三、阶段 ⓪：固定运行边界

每次运行先同步：

- 交易周期、外层周期和观察窗口；
- 当前 Session、剩余交易时间和是否允许跨 Session；
- 当前实际仓位、挂单、成交、保护状态和风险预算；
- 数据完整性、连接、平台和已知事件风险。

运行边界改变时，所有仍在观察的路径都要检查周期、时间和账户约束是否仍相容；改变 entry、stop、目标或持有时间的候选必须重新计算。

## 四、阶段 ①：更新市场事实与活动结构

按照[市场结构与结果路径](market_structure_and_paths.md)依次更新：

```text
K 线与价格事实
→ Push / Leg / Pullback / Pause
→ Separation / Overlap
→ Approach / Test / Breakout Attempt
→ Follow-through / Acceptance / Failure
→ Pressure / Control
→ 活动结构、边界、位置和外层关系
```

这一阶段只使用当时可见事实。候选 measuring gap、final flag、climax 等包含事后结果的名称只能保留候选状态，不能用最终结果回填当前判断。

必要结构边界、观察周期或当前位置无法识别时，不生成交易候选；记录缺失事实并等待。

## 五、阶段 ②：结构生成目标事件

目标是交易形成的上游输入，不是计划完成后的附加退出位。活动结构明确后，先列出当前现实可测试的区域：

- 最近旧高低点、swing、突破点、gap 边界或入场区域；
- 区间内部公平区域、中部和另一侧；
- 趋势线、通道线、EMA 和较高周期区域；
- 已固定结构生成的 measured-move 区域；
- Session 与剩余时间内仍可能到达的其他 magnet。

每个目标必须写成可观察事件，而不只是一个远端价格：

```text
目标事件
- 哪个价格区域：
- 从哪条结构路径到达：
- 图表触及、进入区域还是要求在另一侧获得接受：
- 是否要求账户实际退出成交：
- 观察周期与最迟时间：
```

同一目标区域可能同时是旧高、区间边界、double-test 区域或 measured move。若它们来自同一位置和同一次测试，只形成一个位置证据；不同来源可以说明汇合，但不能按名称数量增加概率。

## 六、阶段 ③：建立当前测试与结果路径

当前测试回答：

> 价格正在检验哪个结构命题？到达目标、返回旧区域或继续未决分别需要出现什么事实？

```text
当前测试

活动结构：
外层关系：
参照区域：
接近方向：
当前位于区域内部 / 外部 / 边缘：
观察周期：
预计时间范围：
正在判断：保持原结构 / 接受新区域 / 返回旧区域 / 结构转换
```

为同一测试建立至少一条目标路径和一条能够实质否定它的反路径；若两者使用不同周期或时间范围，分别保存。路径不是固定二叉树，可以在新结构出现时增加、替代或关闭，但一份 Trade Plan 只能选择其中一条。

每条路径独立经历：

```text
不存在
↓ 结构、目标事件和失效条件明确
观察
├─ 新事实增强或削弱 → 更新条件与概率
├─ 触发仍缺失       → 写明等待项
├─ 可以表达为交易   → 可构造交易
├─ 路径被否定       → 失效
└─ 目标事件发生     → 已完成
```

## 七、阶段 ④：更新路径，而不是堆叠名称

新事实只能产生以下更新：

- 增强目标路径；
- 路径仍成立但减弱；
- 保持未决并继续等待；
- 目标发生；
- 路径失效；
- 新结构替代旧路径。

H2、Double Bottom、Second Entry、Bull Flag 等若描述同一事件链，只帮助说明结构，不产生多份支持。Pattern 关系、状态演化和证据重置见[市场结构与结果路径](market_structure_and_paths.md)。

## 八、阶段 ⑤：匹配条件概率

概率属于目标事件，而不属于形态名称或方向观点。每次使用概率必须同时写明：

```text
已经成立的条件
目标事件
观察周期
时间范围
当前判断时点
适用概率或概率语言
哪个新事实会替代它
```

匹配顺序为：

```text
基础市场状态先验
→ 更具体的结构条件
→ 当前测试和接受结果
→ 当前触发时点
→ 当前 Entry / Stop / Target 的交易估计
```

对相同目标、周期和 horizon，更具体的新条件替代较早的一般规则；概率不相加，也不按理由数量计算。不同目标或 horizon 的概率只作为各自路径背景。完整规则见[条件规则与冲突台账](rules_and_conflicts.md)。

## 九、阶段 ⑥：构造交易并检查方程

按照[交易决策与计划](decision_and_plan.md)检查：

1. 路径是否有明确目标事件、时间范围和失效条件；
2. 是否至少存在两个来源独立且相互补充的支持事实；
3. 最强反方事实是否已使路径或方程失效；
4. 当前是否存在未过期的可观察 Entry；
5. Invalidation 与合理 Protective Stop 是否清楚；
6. 到实际准备兑现目标的空间是否足够；
7. 仓位、成本、时间和管理是否与概率、风险和回报一致。

```text
到达计划结果的概率 × 实际 Reward
>
失败结果的概率 × 实际 Risk + 成本
```

存在部分退出、scratch、主动退出或 scale-in 时，方程必须覆盖计划中的实际互斥结果，不能只使用最有利的一条路径。

## 十、阶段 ⑦：唯一决定

| 决定 | 必须满足 | 输出 |
| --- | --- | --- |
| 执行 | 路径有效；目标、概率、Entry、Invalidation、Stop、仓位、时间和方程完整 | 冻结原始 Trade Plan，进入执行 |
| 等待 | 路径仍可能成立，但缺少目标空间、触发、跟随、清楚边界或当前价格下的合理方程 | 写明等待的具体事实 |
| 不交易 | 路径失效，或空间、时间、风险、成本使交换不值得承担 | 写明被否定的条件 |

等待和不交易都不建立新订单。若后来形成新结构或新 Entry，按当前事实重新建立计划，不能复用较早价格和概率。

## 十一、阶段 ⑧：执行、保护与持仓

执行和持仓生命周期由[执行、持仓与复盘](execution_and_review.md)负责。最低顺序是：

```text
提交订单
→ 确认订单状态
→ 确认实际成交与数量
→ 确认 Active Protective Stop 覆盖实际仓位
→ 持仓中继续更新原 Market Path
→ 目标、主动退出、Stop 或时间条件结束持仓
```

没有实际成交就没有持仓；没有可确认的实际保护就不能假定风险受控。首次成交后冻结入场时的原始 Market Path 与 Trade Plan，后续更新另行记录，不覆盖原始事实。

## 十二、阶段 ⑨：记录所有决定并闭环

复盘不仅记录成交交易，也记录已经形成明确 Market Path 但最终等待、过期或不交易的候选。至少保存：

- 当时可见的结构、目标事件、条件概率和反路径；
- 执行、等待或不交易的原因；
- 原目标事件是否在规定时间内发生；
- 若实际交易，订单、保护、退出、成本与 P&L；
- 偏差来自价格结果、结构判断、概率匹配、计划、风险还是执行；
- 哪些是正常不确定结果，哪些是违反系统契约。

单笔结果不能直接修改条件概率。规则校准只能使用定义一致的连续样本，并在[条件规则与冲突台账](rules_and_conflicts.md)中更新适用条件；实盘复盘不以事后结果重写原判断。

## 十三、系统不变量

- 结构先生成目标；没有目标事件，不匹配概率，也不建立交易。
- 一个概率必须绑定一个目标事件、周期、horizon 和判断时点。
- Pattern 只描述当前事实关系，不选择另一套运行逻辑。
- 一个 Trade Plan 只表达一条 Market Path。
- Entry、Stop、Target、概率和管理不能来自不同判断时点。
- 削弱不等于失效；失效后不能靠旧名称继续维持交易许可。
- 图表事实、订单事实和账户事实分别记录。
- 实时候选与事后名称分开，最终结果不能回填当时理由。
- 等待和不交易都是完整输出，不需要用新交易填补流程。
