# 训练与实盘运行

本页说明怎样在历史回放、实时模拟和实盘中反复运行[Trading System](../trading_system/README.md)。它只负责取样、练习节奏、记录和晋级；Market、Trade、Account 和方法变更仍由原负责页定义，[Examples](../trading_system/examples.md)只验收这些环节的交接。

训练的目标是压缩市场结果的等待时间，在未知、连续的行情中积累可复核的决策经验。`less is more` 在本页表示最小充分：保留所有会改变判断、动作、计划损失或复盘结论的条件，只删除重复对象、无变化的重写和事后叙事。

## 一、共同运行原则

- 训练和实盘运行同一条“位置—预期—进展—路径—交易—仓位”闭环；只有时间速度、成交真实性和资金风险不同。
- 市场按自身时间结构连续处理；日历换日、上线时间或个人值守结束不自动重置市场判断。
- 进入新观察窗口时完整判断一次；随后每根完成 K 都观察，只在新事实改变结论时记录和更新。
- 市场判断持续进行，优先维护会改变当前决定的路径与反方事实；条件不同且确有决策作用时保留竞争解释。
- 同向独立事实可以增强定性判断；多个名称引用同一组价格事实时不重复增加证据、概率、仓位或最大计划损失。
- 同一路径可以先后出现多种参与方式；每种方式分别重算入场、止损、出场、成本和期限，每个决策时点只保留一份当前方案。

日常只按这条主线运行：

```text
新观察窗口完整判断一次
→ 新事实只更新被改变的结论
→ 条件路径支持方案构造，授权前核对实际参与条件
→ 核对订单、实际仓位和止损
→ 交易结束汇总一行并链接判断与执行记录
→ 每日深度复盘少数样本，批次结束再评估方法
```

## 二、运行闭环

### 1. 低频准备

首次使用或产品、账户、数据源及系统版本变化时，固定：

- 产品、数据源、主周期、K 线构造和会改变判断的外层周期；
- tick、数量步长、合约价值、费用、滑点和数据或维护边界；
- 若使用 `R`，固定 `1R` 的计算时点、全仓计划损失口径和成本处理；建仓后不因移动止损或事后路径改写该分母；
- 账户硬限制及 [Account 低频平台检查](../trading_system/account.md#五低频平台检查)；
- 系统版本、生效时间、适用产品和当前训练批次。

训练回放可以使用事前固定的成交与成本假设；实时模拟和实盘只以具体平台记录为准。

### 2. 进入观察窗口

先确定当时最晚可见的可靠数据，再向左读取足以覆盖主问题起点、当前互动、关键结构、路径目标和失效的历史。无法证明数据缺失不影响必要事实时，不形成新路径。

完整展开一张 [Market 运行卡](../trading_system/market.md#二运行卡)：

```text
观察边界：产品、周期、判断时间、最新可靠数据
背景与位置：当前重要区域及其作用
博弈：双方尝试、事前预期、实际进展与跟随、最强反方事实
条件路径：目标与障碍、完成、失效和期限；尚缺的事实
```

重要区域从可复核来源中寻找，只显示当前互动、路径目标与失效参照，以及会实质改变可达性或后续决定的障碍与检查点。关键区域的作用尚不清楚时，补充判断并在条件路径中保留不确定性。

### 3. 按新事实更新

每根新完成 K 都运行：

```text
新事实是什么？
它改变了哪个现有结论？
当前需要什么动作？
```

只保存有变化的答案；无实质变化时继续推进。观察边界或主要解释已经不再适用时，再完整展开 Market 运行卡。

收盘、跟随、回试守住或持续接受是所选条件时，单纯触价不完成它。一次尝试失败先评价该次测试，再判断较大路径是否受损；反向路径使用自己的依据，早期反向 Swing 与持续控制转移分别判断。

### 4. 构造、比较与授权

Market 能支持有目标、失效和期限的条件路径时，就可进入 [Trade](../trading_system/trade.md) 比较方案。未来确认尚未发生时，明确选择提前参与还是等待。实际建仓或加仓授权前核对：

```text
采用的市场预期、交易前提与反方事实有依据
出场已处理目标前的关键障碍
所选入场条件已完成，或能由获准的条件单准确实施
入场、止损、出场和期限组成同一套可执行方案
期限、剩余空间和成本后交换仍较有利
数量与最大计划损失符合账户硬限制
平台能够在事前边界内执行并保护实际仓位
```

选择一份当前执行方案；不合格时等待或放弃。更多确认可以伴随更差入场，更好价格可以伴随更少确认；使用每个决策时点真正可得的证据和价格。同一路径因正常回试、成本或时间变化改善交换时可以重评。

### 5. 执行与持仓

按 [Account](../trading_system/account.md) 的依赖顺序核对授权、订单接受、触发、成交、实际仓位和平台实际止损。只有实际成交改变仓位。

Market 继续判断，Trade 按实际仓位、保护、交易前提与当前交换决定持有、加仓、减仓或平仓。执行与期限变化也会触发重评。加仓需要完整方案及整笔风险重算；减仓按决定时的实际数量转为目标余仓，迟到成交按 Account 处理。

平台记录不清时不把未知填成零；停止建仓或加仓，查询并撤销可能扩大仓位的订单，再按事前安全边界恢复止损、减仓或平仓。

### 6. 结束与再次参与

只有实际仓位为零，且所有相关订单均已完成、取消或不再可能成交时，本笔交易才结束。市场判断和新方案比较始终继续；同品种下一笔授权在旧执行风险清理后开始。

路径实现固定原市场结果。新事实可以支持后续路径及余仓方案，也可以改变尚未成交的普通出场；保留旧决定与实际成交，按 Trade 更新、Account 核对，已退出数量不会自动买回。保护性止损执行、账户超限和已到的安全期限继续减险。

## 三、历史回放

### 取样

- 从目标产品实际准备交易的全部时段中随机抽取历史起点；若实盘只计划在固定值守时段交易，则只在该时段中随机。
- 不按趋势、回调、区间、突破、高潮或反转挑选日期；场景只能在回放过程中按当时已知事实查询，或事后标记。
- 只显示回放起点之前的信息；不拖动查看未来，不回退重做，不用后来事实改写原判断。
- 每次连续推进事前固定的观察时长。到时仍有相关订单或仓位时，继续到本笔交易结束；空仓且相关订单均不再可能成交后才结束该窗口。

历史回放中的图表触价、历史下单界面和实际 Broker 成交能力仍是不同事实。同一根 K 同时包含止盈和止损价、而现有数据粒度无法确认先后时，记为“先后未知”；事前采用保守代替规则时，必须对全部样本一致使用。

### 速度与数量

完整判断还不稳定时可以暂停并查询负责页；稳定后逐步减少暂停，直到能够连续推进未知窗口。加速只压缩现实等待时间，不缩短路径、交易或数据可靠性的事前期限。

每个现实训练日可以通过多个随机历史窗口累计 `10–100` 笔自然产生的交易。数量不足时继续下一随机窗口；不在当前窗口降低路径或交易完整标准。

## 四、实时模拟与实盘

### 实时模拟

实时模拟不再压缩时间，用于验收：

- 等待下一可靠事实时能否保持空仓；
- 订单提交、撤单、替换、部分成交、止损覆盖和残余订单核对；
- 数据、连接或平台记录不清时的安全动作；
- 个人值守结束前的未成交订单和已有仓位处理。

模拟成交用于验收执行流程，不证明真实滑点、排队、拒单或平台能力。

### 实盘

实盘不设最低交易笔数。市场产生的合格方案可以是 `0` 笔或多笔；数量目标不得降低路径、交易或账户标准。

市场可以连续交易，人的值守能力不连续。实盘事前确定值守开始、停止新建仓、值守结束，以及届时对未成交订单、实际仓位和平台实际止损的确定性处理。离开时仍保留仓位，只能来自建仓前已验证的无人值守方案，不得在值守结束时临时决定。

从实时模拟进入实盘时先使用最小可执行数量，只验证：

- 真实成交、费用、滑点和订单限制是否与方案相容；
- 实际资金是否导致追价、提前退出、放宽止损、计划外加仓或报复交易；
- 账户硬限制、实际仓位和平台实际止损能否持续正确核对。

增加数量只能在事前定义的完整批次后进行。任一账户硬限制违反、止损覆盖或平台记录无法可靠核对，以及实际成本或执行明显破坏方案时，停止增加并回到上一已验证数量或模拟。

## 五、最小记录

记录的职责是保留当时判断和最早偏差，不是重写负责页。

### 观察窗口记录

进入新窗口或完整重判时保存 Market 运行卡。随后只保存改变结论的事件：

```text
时间 | 新事实 | 改变的结论 | 当前动作
```

### 每笔交易记录

```text
ID | 产品 | 时间 | 方向 | 入场 | 止损 | 计划出场 | 期限 | 计划 R | 实际 R | 退出结果 | 执行合规 | 最早偏差
```

结果仍按[Governance](../trading_system/governance.md#五复盘时分开四个结果)分开：

```text
Market：待定 / 实现 / 失效 / 到期 / 先后未知；停止采用另记时间与原因
Trade：止盈 / 止损 / 主动平仓 / 到期 / scratch / 分批出场 / 无成交
Account：实际成交 / 费用 / 滑点 / 持有成本 / 净结果
Process：判断 / 方案 / 风险 / 仓位 / 执行是否合规，以及最早偏差
```

每笔交易汇总一行，链接当时判断、方案及变更、订单请求和实际成交记录。只对能代表正确执行、重复偏差、判断困惑或新研究问题的少数样本展开完整截图和长复盘。

## 六、复盘、批次与晋级

### 每日复盘

汇总：

```text
交易笔数 / 等待 / 放弃 / 无成交
净 R / 费用 / 最大连续损失
授权前方案完整率 / 执行合规率
最常见的最早偏差
```

每日只选少数有信息增量的样本深度复盘，包括合规盈利、合规亏损、获利但违规、重复偏差或无法解释中的实际命中类别。赚钱不自动证明判断和执行正确，亏损也不自动证明市场判断错误。

### 批次复盘

历史回放默认每 `100–200` 笔交易形成一个批次。批次内固定系统版本、取样规则、成本假设和先后未知处理，不因单笔或短期连续结果修改方法。

批次结束后先区分：

1. 规则已清楚但未遵守的执行问题；
2. 现有规则正确但运行时难以快速调用的表达问题；
3. 在相同条件下连续出现的可复现方法问题。

只有第三类进入 [Governance 方法变更](../trading_system/governance.md#七方法变更)。新版本只影响生效后的判断，不回头修改旧样本。

### 晋级与退回

```text
历史回放
→ 实时模拟
→ 最小可执行数量实盘
→ 事前定义的分级数量
```

晋级不由单笔盈亏决定。进入下一阶段前，至少必须有多个完整批次证明：

- 当时判断、交易方案和记录可以复核；
- 不通过偷看、事后改写、挑选样本或重复名称美化结果；
- 授权前方案完整率和执行合规率稳定，且没有账户硬限制违反；
- 订单、实际仓位和平台实际止损可以持续核对；
- 实际成本、执行能力和运行负荷不会破坏方案或仓位安全。

任一安全边界不再成立，或增加数量后稳定执行明显退化时，停止晋级并回到上一已验收阶段。
