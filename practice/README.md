# 训练与实盘运行

本页说明怎样在历史回放、实时模拟和实盘中反复运行[Trading System](../trading_system/README.md)，包括取样、练习节奏、记录，以及执行能力与经济表现的验收。市场判断、交易方案、平台执行和方法变更的详细规则见各页；[Examples](../trading_system/examples.md)用于检查连续事件中的判断和交接。

训练在未知、连续的行情中积累可复核的决策经验。历史回放压缩等待时间，实时模拟和实盘检验实际节奏下的判断与执行。记录保留影响决定的事实和变化，未变化的内容沿用。

## 一、共同运行原则

训练与实盘统一按[核心闭环](../trading_system/README.md#核心闭环)处理首次建立、事件更新和本次判断结束；只有时间速度、成交真实性和资金风险不同。随后每根完成 K 都观察，记录改变判断、方案或执行状态的新事实；已有可靠判断、共享事实和未变化的管理沿用。

市场按自身时间结构连续处理；日历换日、上线时间或个人值守结束不自动重置市场判断。竞争解释与候选参与方式按主入口比较，只展开影响当前选择的内容；实际授权仍须满足 Trade 和 Account 的方案、仓位及执行要求。

## 二、运行闭环

### 1. 低频准备

首次使用或产品、账户、数据源及系统版本变化时，固定：

- 产品、数据源、主周期、K 线构造和会改变判断的外层周期；
- tick、数量步长、合约价值、费用、滑点和数据或维护边界；
- 若使用 `R`，固定 `1R` 的计算时点、全仓计划损失口径和成本处理；建仓后不因移动止损或事后路径改写该分母；
- 账户硬限制及 [Account 低频平台检查](../trading_system/account.md#五低频平台检查)；
- 系统版本、生效时间、适用产品和当前训练批次。

训练回放可以使用事前固定的成交与成本假设；实时模拟和实盘只以具体平台记录为准。

初期可先固定一个能力范围或机会族、一种参与方式和一种简单管理基准，例如只练习突破后回试参与，并按事前结构保护和目标管理。在相同连续窗口中仍观察其他机会；超出本次能力范围时记录未参与的原因，不必构造所有交易方案。比较其他方式时，在读取未来前固定对照方案，使用各自当时可得的价格，计入未成交、重入、成本和运行负荷。执行者已看过后续的窗口用于训练或设计，经济检验另取未知窗口；按事前完整规则复算的结果另记为规则回放。

### 2. 盘中运行导航

首次进入窗口或接管、每次更新和结束本次判断，都从[核心闭环](../trading_system/README.md#核心闭环)进入，详细规则按主入口导航查询。正常回调、双边化、退出与重新参与示例见[连续事件验收](../trading_system/examples.md)；需要比较管理选择时，先练习[同一前缀下的管理比较](../trading_system/examples.md#同一前缀下的管理比较)。

历史回放的暂停、推进与取样按下一节执行；记录采用[最小记录](#五最小记录)。

## 三、历史回放

### 取样

- 从目标产品实际准备交易的全部时段中随机抽取历史起点；若实盘只计划在固定值守时段交易，则只在该时段中随机。
- 不按趋势、回调、区间、突破、高潮或反转挑选日期；场景只能在回放过程中按当时已知事实查询，或事后标记。
- 只显示回放起点之前的信息；不拖动查看未来，不回退重做，不用后来事实改写原判断。
- 每次连续推进事前固定的观察时长。到时仍有相关订单或仓位时，继续到本笔交易结束；空仓且相关订单均不再可能成交后才结束该窗口。

历史回放中的图表触价、历史下单界面和实际 Broker 成交能力仍是不同事实。同一根 K 同时包含止盈和止损价、而现有数据粒度无法确认先后时，记为“先后未知”；事前采用保守代替规则时，必须对全部样本一致使用。

### 速度与进度

完整判断还不稳定时可以暂停并查询负责页；稳定后逐步减少暂停，直到能够连续推进未知窗口。加速只压缩现实等待时间，不缩短路径、交易或数据可靠性的事前期限。

训练进度按事前安排的连续观察窗口推进，不设每日最低交易笔数。一个窗口自然产生零笔交易，也属于有效样本；不为凑数量延长当天训练、挑选行情或降低参与标准。交易数只描述产生了多少交易，不能代替观察时间、机会覆盖或学习效果。

## 四、实时模拟与实盘

### 实时模拟

实时模拟不再压缩时间，用于验收：

- 等待下一可靠事实时能否保持空仓；
- 订单提交、撤单、替换、部分成交、止损覆盖和残余订单核对；
- 数据、连接或平台记录不清时的安全动作；
- 个人值守结束前的未成交订单和已有仓位处理。

模拟成交用于验收执行流程，不证明真实滑点、排队、拒单或平台能力。

### 实盘

实盘不设最低交易笔数。市场产生的合格方案可以是 `0` 笔或多笔；数量目标不得降低路径、交易或账户标准。

市场可以连续交易，人的值守能力不连续。实盘事前确定值守开始、停止新建仓、值守结束，以及届时对未成交订单、实际仓位和平台实际止损的确定性处理。离开时仍保留仓位，只能来自建仓前已验证的无人值守方案，不得在值守结束时临时决定。

从实时模拟进入实盘时先使用最小可执行数量。在开始前限定可承担的学习损失、观察期限、复核时点以及停止或退回条件；最小数量仍超过学习预算时，继续模拟。这个阶段检验：

- 真实成交、费用、滑点和订单限制是否与方案相容；
- 实际资金是否导致追价、提前退出、放宽止损、计划外加仓或报复交易；
- 账户硬限制、实际仓位和平台实际止损能否持续正确核对。

进入最小实盘表示允许承担有限学习风险，不表示方法已证明盈利。达到学习损失或期限边界时停止新增风险，终止尚未成交的建仓、加仓授权，由 Account 撤单并核对迟到成交，按既定退出和保护方案处理实际余仓，再复核是否退回模拟；不得靠增加数量弥补学习亏损。

增加数量须同时通过[执行能力与经济表现验收](#晋级与退回)。任一账户硬限制违反、止损覆盖或平台记录无法可靠核对，以及实际成本或执行明显破坏方案时，停止新风险，按 Account 处理已有风险，并回到上一已验收数量或模拟。

## 五、最小记录

记录的职责是保留当时判断和最早偏差，不是重写负责页。

### 观察窗口记录

进入新窗口或完整重判时保存 Market 运行卡。随后只保存改变结论的事件：

```text
时间 | 新事实 | 改变的结论 | 当前动作
```

### 每笔交易记录

```text
ID | 产品 | 时间 | 方向 | 入场 | 止损 | 计划出场 | 期限 | 计划 R | 实际 R | 退出结果 | 执行合规 | 最早偏差
```

结果仍按[Governance](../trading_system/governance.md#五复盘时分开四个结果)分开：

```text
Market：待定 / 实现 / 失效 / 到期 / 先后未知；停止采用另记时间与原因
Trade：止盈 / 止损 / 主动平仓 / 到期 / scratch / 分批出场 / 无成交
Account：实际成交 / 费用 / 滑点 / 持有成本 / 净结果
Process：判断 / 方案 / 风险 / 仓位 / 执行是否合规，以及最早偏差
```

每笔交易汇总一行，链接当时判断、方案及变更、订单请求和实际成交记录。同一段行情中的退出、重入、未成交和未参与机会通过观察窗口记录连接，不因重新建仓而丢失之前的成本和决定。未参与机会只记录当时理由与可见条件；没有预先固定的对照方案时，不补算假想收益。只对能代表正确执行、重复偏差、判断困惑或新研究问题的少数样本展开完整截图和长复盘。

## 六、复盘、批次与晋级

### 每日复盘

汇总：

```text
交易笔数 / 等待 / 放弃 / 无成交
成本后净结果 / 净 R / 费用 / 权益回撤 / 最大连续损失
授权前方案完整率 / 执行合规率
最常见的最早偏差
```

每日只选少数有信息增量的连续过程深度复盘，包括合规盈利、合规亏损、获利但违规、重复偏差或无法解释中的实际命中类别。检查一次退出减少了什么风险、随后是否重入、整段付出多少成本，以及错失或多余操作是否来自可修正的决定。赚钱不自动证明判断和执行正确，亏损也不自动证明市场判断错误。

### 批次复盘

批次开始前说明验证对象，固定系统版本、能力范围、连续窗口的长度与取样范围、管理基准、成本假设和先后未知处理，并约定风险收益目标、评价与停止条件。批次按这些窗口完成，不因交易笔数不足、短期盈亏或希望得到某个结论而增删样本；停止条件触发的批次保留并说明。

验证执行者的整套裁量时，固定执行者及其选择惯例，说明同类条件下通常怎样参与、持有或调整，以及允许例外的依据；结果属于这名执行者在该版本和范围内的整体表现。验证单项新增判断时，先固定采用与不采用它的完整比较方案，使其余相关选择和风险条件可比，才能评价这项判断的增量。具体边界按 [Governance 方法变更](../trading_system/governance.md#七方法变更)确定。

训练探索用于形成或修改选择惯例和比较方案，记录改变及依据；受这些调整影响的窗口不能与固定方案后的检验窗口混算为同一版本证据。检验另取执行者未知的连续窗口，按事前惯例响应新事实仍属正常裁量。探索和检验都遵守当时有效的账户、安全与取样边界。

交易笔数与连续时段共同报告。同一段行情内的多次进出具有依赖关系，不能把重入次数当成独立证据；按完整窗口或相关行情过程汇总成本后结果、回撤和机会处理，再观察不同窗口间的差异。一个有利行情贡献大部分收益、样本未覆盖计划交易时段或成本假设不可靠时，应降低对结果的信心。固定方法后新收集的窗口用于继续检验，选来修改方法的旧样本不能单独支持加量。

批次结束后先区分：

1. 规则已清楚但未遵守的执行问题；
2. 必要信息难以快速调用、重复记录或无助于动作选择的表达问题；
3. 在相同条件下连续出现的判断、参与或管理方法问题。

纯执行偏差通过训练纠正；涉及规则、组织或记录义务的调整，按 [Governance 方法变更](../trading_system/governance.md#七方法变更)选择相应验证。新版本只影响生效后的判断，不回头修改旧样本。

### 晋级与退回

```text
历史回放
→ 实时模拟
→ 最小可执行数量实盘
→ 事前定义的分级数量
```

晋级分别回答两个问题，并在批次开始前写明评价基准、证据需求、不确定性及停止或退回条件。

**执行能力是否支持下一阶段。** 历史回放与实时模拟按该项验收，进入最小数量实盘还须满足上述有限学习条件：

- 当时判断、交易方案和记录可以复核；
- 不通过偷看、事后改写、挑选样本或重复名称美化结果；
- 授权前方案完整率和执行合规率稳定，且没有账户硬限制违反；
- 订单、实际仓位和平台实际止损可以持续核对；
- 实际成本、执行能力和运行负荷不会破坏方案或仓位安全。

**经济表现是否支持增加风险。** 增加数量前，除执行能力外，还必须有固定版本在事前约定的连续窗口中取得的证据：

- 计入实际费用、滑点、持有成本以及整段退出和重入后，净表现支持继续承担更多风险；
- 权益回撤、损失持续时间及不同窗口的表现符合事前可承担范围；结果对少数有利行情的依赖已识别并纳入不确定性评价；
- 与事前选定的简单管理基准比较，新增管理按风险收益目标带来可说明的改善；可以接受部分净收益减少以换取更低回撤或更稳定执行，仍须满足净表现和风险底线，并计入新增成本与负担。未采用复杂操作时直接评价基准本身；
- 证据的适用范围、成本与成交差异、窗口依赖和尚未覆盖的行情明确，增加后的数量与执行条件仍相容。

不设通用胜率、固定笔数或收益阈值；评价基准和风险限额须在看见批次结果前确定。持续成本后净亏、回撤超出预定范围或证据不足时不增加数量；一次盈利或若干合规批次均不能替代经济验收。模拟收益只能提供候选证据，真实成本和执行学习仍须完成。

增加后继续按同一评价边界复核，不把旧数量下的表现直接外推。任一安全边界不再成立、稳定执行明显退化或达到事前经济停止条件时，停止新增风险，安全处理已有订单与仓位，并回到上一已验收数量或模拟；证据不足但未触及停止条件时保持当前数量，继续按事前计划取样。
